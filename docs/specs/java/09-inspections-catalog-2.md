# 09. Java inspections catalog, part 2

Status: specification, clean-room. Written from the IntelliJ IDEA Community sources in our own words. Message
templates, option labels and fix names are quoted from the message bundles (short user-visible strings). Source
paths are cited as `ic: <path>`. No code is reproduced.

Part 2 covers the inventory file `inventory/inspections-java-2.md`: JVM languages (language-neutral API and
test-support inspections), TestNG, and the Java groups Abstraction, Assignment, Bitwise operation, Class metrics,
Class structure, Cloning and Code maturity. How to read the tables, the priority rule and the case conventions are
the same as in `09-inspections-catalog-1.md` (section 9.1) and in `cases/README.md`. Rows that only point to an
existing requirement (`JAVA-INS-*`, `CI-INS-*`) are listed under "Covered by existing specs".

Primary sources: `ic: java/java-backend/resources/META-INF/InspectionGadgets.xml`,
`ic: jvm/jvm-analysis-impl/` (the JVM group and its tests under `ic: jvm/jvm-analysis-java-tests/`),
`ic: java/java-analysis-impl/src/com/siyeh/ig/` and `ic: java/java-impl/src/com/siyeh/ig/` (the gadget
inspections), message bundles `InspectionGadgetsBundle.properties`, `JvmAnalysisBundle.properties`,
`JavaAnalysisBundle.properties`, `ic: plugins/testng/` (TestNG), descriptions under
`ic: java/*/resources/inspectionDescriptions/`.

## 9.5 Open questions

- **Global inspections** (`EmptyMethod`, `StaticMethodOnlyUsedInOneClass`, `MethodReturnAlwaysConstant`) run only
  in the batch flow; cases use the key `inspect batch`. Whether Archipel also shows `EmptyMethod` on the fly for
  the open file (the unused-declaration style subset of `07-inspections.md` 7.2) is decided there, not here.
- **Refactoring-launching fixes** (`Convert to named inner class`, `Convert to inner class`, `Introduce constant...`,
  `Replace constructor with factory method`, `Move member to usage class`): the catalog fixes the fix names and
  the refactoring they start; the dialogs are specified with the refactoring specs (`REF`).
- **Library-declared API** (`NonExtendableApiUsage`, `OverrideOnly`, `UnstableApiUsage`) depends on telling
  library classes from project sources (`--- library:` files in cases).
- **TestNG** inspections assume the TestNG library is attached; `UndeclaredTests` needs the `testng.xml` suite
  file model of the TestNG plugin.
- **`SourceToSinkFlow`** is specified at the level of its entry points, messages and options; the full
  propagation rules (depth limits, method matchers, qualifier cleaners) are an implementation decision that must
  keep the observable highlights listed in the cases.
- Fix texts marked `status: unverified` come from templates and tests, not from a running IDE.
