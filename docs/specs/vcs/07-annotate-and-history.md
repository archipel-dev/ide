## 1. Annotate

| ID | Pri | Requirement | Acceptance |
|---|---|---|---|
| VCS-ANN-001 | MUST | `Annotate` (`Annotate`; Git menu entry text `Annotate with Git Blame`; editor gutter context menu and Git file actions; no default shortcut; description `Show the latest modification date and author for each line (also known as "Blame")`) toggles an annotation column in the left gutter of the editor. It is a toggle: while shown the action reads `Hide`-like state (checked). Disabled for directories (`Cannot annotate directory`) and files without VCS history. Progress/placeholder `Loading Annotations` / `Computing annotation for <file>`. | Right click the gutter on a tracked file > Annotate: a column with author names appears. |
| VCS-ANN-002 | MUST | Each annotated line shows: author (short form per `Names` setting: `Initials`, `First Name`, `Last Name`, `Full Name`, `Email`; default full name unless the column is narrowed) and the date (relative to locale short date); lines not yet committed show `Not committed yet`. The column width fits the longest entry; revision number can be shown through `Revision` aspect. Gutter group `View` (`annotate.action.view.group.text`) toggles aspects `Author`, `Date`, `Revision` (`Commit number`) and the color mode submenu. | Edit a line without saving the VCS: the annotation of that line reads `Not committed yet`. |
| VCS-ANN-003 | MUST | Background coloring: color modes `Author`, `Order` (by commit age), `Hide` (group title `Colors`); colors are drawn from five scheme anchors `VCS_ANNOTATIONS_COLOR_1..5` (light: `a1bef7`, `c9dafb`, `dee8fc`, `edf2fa`, `f7f8fa`; dark: `2f5194`, `2d416b`, `283754`, `242d42`, `22252e`) interpolated linearly with 4 steps between anchors (so up to 21 colors) and shuffled with step 4 to separate neighbors; `Order` mode maps newest to the first anchor. | The newest commit's lines use anchor 1 color. |
| VCS-ANN-004 | MUST | Tooltip on an annotated line shows the commit: `commit <hash>`, `Author: <name>`, `Date: <date>`, `Path: <path>` (if differing), followed by the commit message; for blame in the new UI the hover can show the diff (`Show Diff On Hover`, toggle). A click on the annotation selects the commit; the gutter popup (`Vcs.Operations.Popup.Annotate`, text `Annotated Line Operations`; group `Annotated Line`) offers: `Show Diff` (`Show Diff from Annotation`), `Annotate Revision` (`Annotate the selected revision in a new tab`), `Annotate Previous Revision` (`Annotate the successor of the selected revision in a new tab` for the successor action), `Copy Revision Number`, `Select in Git Log`/`Show in VCS Log`, `Show All Affected Files` (`Alt+Shift+A`), `Hide merge sources` / `Show merge sources` (`Revision: <n>` original revision text). | Click an annotation > Show Diff: the diff of that commit for the file opens. |
| VCS-ANN-005 | MUST | Annotation stays aligned with the document while editing: line mapping is updated on edits (via the line-status tracker), lines changed locally are labeled `Not committed yet` immediately; after save the annotation reloads. Mismatch between annotated line count and document: notification `Number of lines annotated by <vcs> is not equal to number of lines in the file. Check file encoding and line separators.` Errors: `Cannot load annotations`, `Annotated line is out of bounds: <i>, total line count: <n>`. | Insert a line above: annotations shift down without flicker. |
| VCS-ANN-006 | SHOULD | Git blame options in the gutter menu group `Options`: `Ignore Whitespaces` (default **on**, `ANNOTATE_IGNORE_SPACES`), `Detect Movements Within File` (inner), `Detect Movements Across Files` (outer); stored `ANNOTATE_DETECT_INNER_MOVEMENTS` default `NONE` (values NONE, INNER, OUTER). Shallow repositories warn `Annotations might be inaccurate in the shallow repository`. | Toggling `Ignore Whitespaces` reloads the annotation with `-w`. |
| VCS-ANN-007 | SHOULD | Advanced setting `Load file annotations from VCS when file is opened in editor` (`vcs.annotations.preload`, default **off**, description `This allows showing them faster on demand`). Annotation of a revision (from history) opens in a new editor tab titled by revision; `Annotate Revision` in history context menu (`FileHistory.AnnotateRevision`, `Vcs.Log.AnnotateRevisionAction`, same text `Annotate`). | Default: no blame is computed on open. |
| VCS-ANN-008 | SHOULD | Stack-trace modification info: `Show Files Modification Info` (`AnnotateStackTraceAction.show.files.modification.info`) annotates files in an external stack trace by last modification; setting `Highlight files changed in the last <n> days` (default off, max days constant). | Toggle in the analyze-stacktrace toolbar. |
| VCS-ANN-009 | SHOULD | Code author inlay hints: `Code Author` hints above declarations with `<author> +<n>` forms (`new *`, `<author> *` when the author's code is modified locally, `<author> +<n>`, `<author> +<n> *`), description `The author of the code according to the records in the VCS.` Off by default in settings (Editor > Inlay Hints > Code Author). | Hint text formats match. |

## 2. File history

| ID | Pri | Requirement | Acceptance |
|---|---|---|---|
| VCS-HIST-001 | MUST | `Show History` (`Vcs.ShowTabbedFileHistory`; Git menu, editor tab/Project view context menu `Git > Show History`; text with file `Show History for <file>`; no default shortcut) opens a `History` tab for the file or directory in the Git tool window using the log-table UI: columns Commit (subject), Author, Date, Hash hidden; toolbar and context menu per VCS-LOG-040; the right/bottom details show commit message and changed files; a left-most `Show file names` option (default off) shows the file path when it changed (renames). History follows renames (`git log --follow` semantics/`--full-history --simplify-merges` when registry `git.file.history.full` is true, default true). Loading text `Loading file history`, `Loading history for <file>...`, `Loading history for <file> up to <rev>...`; errors `Problems while loading file history`. | History of a renamed file lists commits on both names. |
| VCS-HIST-002 | MUST | History limit: with `Limit history to N rows` on (`LIMIT_HISTORY` default on, 1000) the message `File History: only <n> revisions were loaded for <file>. To change the history limit, go to <settings path>` appears. Directory history uses the log with a path filter. | A 2000-commit file shows the limit message. |
| VCS-HIST-003 | MUST | Actions on selected revisions (toolbar `Refresh` is `Vcs.RefreshFileHistory`, shortcut of `Refresh`): `Show Diff` (`Ctrl+D`; one revision compares with its parent `Show diff with previous version`; two revisions `Compare` / `Compare selected versions`), `Compare with Local` (`Vcs.ShowDiffWithLocal`), `Compare Before with Local` (`Vcs.ShowDiffWithLocal.Before`), `Get` (`Vcs.GetVersion`, `Get a version from the repository`; error `Cannot load revision`, `Cannot save content`), `Show File at Revision` (`Vcs.Log.OpenRepositoryVersion`), `Create Patch...`, `Copy Revision Number`, `Show All Affected Files` (`VcsHistory.ShowAllAffected`, `Alt+Shift+A`), `Annotate`, `Show in VCS Log`, `History Up to Here` (`Vcs.ShowHistoryForRevision`, `Show history for a file until the selected revision`; title `<file> at <rev>`). | `Ctrl+D` on one revision opens its diff against the parent. |
| VCS-HIST-004 | MUST | Merge commits in file history: the diff asks `Choose Parent to Compare`; when the file has no changes in a merge: `There are no changes to file <f> in this merge commit`. | Diff of a merge entry offers a parent chooser. |
| VCS-HIST-005 | SHOULD | `Show History for Selection...` (`Vcs.ShowHistoryForBlock`; synonyms `Show History for Method...`, `Show History for Class...`) opens `<file> history for selection`: a table of revisions that touched the selected lines (columns Revision/`Date`/`Author`/message) and a diff of the selected block between consecutive revisions; loading `Loading revision <n>...`, `Commit Message:`, `Local Changes` row, `Cannot load revision contents`; availability: needs a selection (or the caret's block); shortcuts none. `Local History > Show History for Selection...` is the separate local variant (VCS-LH-020). | Select 3 lines > action: only revisions touching those lines list. |
| VCS-HIST-006 | MUST | `Compare with Same Repository Version` (`Compare.SameVersion`, `Ctrl+D` in the project view for a single changed file: opens the diff with the base revision) / `Compare with Latest Repository Version` (`Compare.LastVersion`, SVN-like, LATER) / `Compare with Revision...` (`Compare.Selected`: lists revisions `File Revisions` popup then diffs with local) / `Compare with Specified Revision...` (`Compare.Specified`) / `Compare with Branch or Tag...` (VCS-BR-041). Popups use titles `File Revisions`; empty `History is empty`, `No revisions`. | `Compare with Revision...` shows the revision list popup and opens the diff for the chosen one. |
| VCS-HIST-007 | SHOULD | `Show Current Revision` (`Show.Current.Revision`) opens a read-only editor with the base revision content (`Revision: <n>`); `Load Revision Contents`/`Loading Current Revision...` progress; failure `Cannot load revision: <msg>`. | Opens `HEAD` content in a read-only tab. |
| VCS-HIST-008 | SHOULD | Paths from repository root: `Path From Repository Root` (`CopyPathFromRepositoryRootProvider`) in the Copy Path/Reference group copies the root-relative path. `Show in Git Log` link from the history of other VCS plugins reads `Show in Git Log`. | Copy action yields a relative path with forward slashes. |
| VCS-HIST-009 | SHOULD | Committed changes browser (centralized VCS): `Browse Changes...` (`ChangesView.Browse`), `CommittedChanges.Refresh` (`Refresh Committed Changes`), `CommittedChanges.Filter` (with `Filter by`, `Group by`, `Regex`), `CommittedChanges.Details` (`Show Details`), `CommittedChanges.Revert` (`Revert Changes`: `Apply the reverse of the selected changes to the working copy`), `CommittedChanges.Clear` (`Clear`: `Clears cached revisions`), incoming tab (`Incoming`, `IncomingChanges.Refresh`, status widget `IncomingChanges`), `Integrate` (`IntegrateFiles`, `Vcs.IntegrateProject`), `Update` (`UpdateFiles`), `Check Status` (`CheckStatusForFiles`), `Check Out` (`ChangesView.Edit`). Texts `There are no committed changes in the repository`, `Press Refresh button to load repository changes`, `No incoming changelists available`. Git does not use these (no committed-changes provider); keep as extension surface. | Not exercised by Git projects. |

## 3. Navigation by change markers and VCS utilities

| ID | Pri | Requirement | Acceptance |
|---|---|---|---|
| VCS-HIST-020 | MUST | `Vcs.QuickListPopupAction` (`VCS Operations Popup...`, `Alt+Backquote`) shows the `VCS Operations` popup: for a project under Git a list containing Commit, Update, Push, Branches, Show History, Annotate, Compare, Rollback, Local History, etc.; for non-VCS projects entries `Enable Version Control Integration...`, `Create Git Repository...`, `Local History...`. `Vcs.Toolbar.ShowMoreActions` / `Git.Toolbar.ShowMoreActions` (text `Version Control`, description `VCS Operations`) is the toolbar variant. | `Alt+Backquote` opens the popup titled `VCS Operations`. |
| VCS-HIST-021 | SHOULD | `Mark File Dirty in VCS` (`MarkFileDirty`, internal). `Close Unmodified Tabs` (`CloseAllUnmodifiedEditors`, in tab context menu) closes editors of files without VCS changes. | Internal action registration; the second closes tabs whose files are not modified. |
