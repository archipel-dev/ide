# 09-7. Java inspections catalog, part 7 (probable bugs, properties files, reflective access, resource management)

Status: specification, clean-room. Written from the IntelliJ IDEA Community sources in our own words. Message
templates, option labels and quick-fix names are quoted from the message bundles (short user-visible strings).
Source paths are cited as `ic: <path>`. No code is reproduced. Inventory: `docs/specs/inventory/inspections-java-7.md`.
Requirement ID prefix: JAVA-ICC. Framework (severities, profiles, suppression, batch run): `docs/specs/codeinsight/03-inspections.md`;
the 40 most used inspections are in `docs/specs/java/07-inspections.md` (JAVA-INS) and are only cross-referenced here.

## 0. How to read the tables

- **Default**: `on`/`off` = enabled by default; the level is the default severity (WARNING = yellow wavy, WEAK WARNING,
  ERROR, INFO = no marker, only an intention). Priority: MUST = enabled by default, SHOULD = disabled by default, LATER = obsolete or
  out-of-scope technology (reason given).
- **Message**: the problem text from the bundle. `#ref` is the text of the highlighted element; `{0}`, `{1}` are
  substituted values. In HTML tooltips `<code>` is rendered monospace.
- **Range**: what is underlined. "name" is the name identifier, "call" the method name of a call expression, unless stated.
- **Fixes**: the exact names shown in the Alt+Enter menu. "Replace with ''{0}''" shows the replacement text, e.g. `Replace with 'Arrays.equals()'`.
- **Kind**: all inspections here are local (run in the editor and in batch) unless the row says *batch only* (global).
- Suppression is the common mechanism: `@SuppressWarnings("<ShortName>")` or `//noinspection <ShortName>`.
- Executable cases: `docs/specs/java/cases/09-inspections-7.cases.md` (keys `Alt+Enter, choose "<fix>"`; `inspect` = look at the
  highlight; the `after` block then lists `problem: <level> <range text> "<message>"` lines).
- Inspections already specified in JAVA-INS are one-line rows that reference the existing ID.

## 4. Java / Resource management (8)

Common to the six "opened but not safely closed" inspections (`ChannelResource`, `HibernateResource`, `IOResource`, `JDBCResource`,
`JNDIResource`, `SocketResource`): they report the expression that creates (or obtains) the resource when it is
assigned to a variable or used and is not closed in a `finally` block or `try`-with-resources. The resource is
considered closed when `close()` or `cleanup`-named method (any method with `close`/`cleanup` in its name) is called on it, or, with the
option, when it is passed as argument to any method (`Any method may close resource argument`, on). Resources
wrapped by another resource, returned from the method, assigned to a field, or passed to a constructor of another
closeable are not reported. Common message: `'{0}' should be opened in front of a 'try' block and closed in the corresponding 'finally' block`
(range: the creating call or `new` expression; `{0}` the type). Common options: `Allow resource to be opened inside a 'try' block`

1. The registrations and bundles for `UnresolvedPropertyKey` and `UnsupportedCharacter` are not in the sparse
   source tree; their message texts are taken from the deprecated/analysis bundles and must be confirmed.
2. Fix names that come from shared helpers (type-cast, rename, equals) are written with their standard bundle template; the substituted
   text (`{0}`) is the replacement shown in the menu.
