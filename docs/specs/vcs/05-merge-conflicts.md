## 1. Where conflicts surface

| ID | Pri | Requirement | Acceptance |
|---|---|---|---|
| VCS-MERGE-001 | MUST | A Git conflict entry has a type derived from the two status letters: `both modified`, `both added`, `both deleted`, `added by you`, `added by them`, `deleted by you`, `deleted by them`. Conflicted files appear in Local Changes under the node `Merge Conflicts` (with link `Resolve`; after resolution under `Resolved Conflicts`) and in the status coloring as merged-with-conflicts (VCS-CHG-051). | After a conflicting merge the node lists the files with the type strings. |
| VCS-MERGE-002 | MUST | The Changes view shows a banner `Cannot proceed due to merge conflicts` with a default action `Resolve...` when an operation (merge, rebase, cherry-pick, update) stopped on conflicts. `Resolve Conflicts...` (`Git.ResolveConflicts`, Git menu and merge widget) opens the conflicts dialog for all unmerged files; it is disabled when there are none (and shows `The conflict seems to be resolved` / title `No Conflict Found` when invoked for a resolved file). | Conflicted merge: banner and action visible. |
| VCS-MERGE-003 | MUST | Editors of files with conflict markers show a notification banner `File has unresolved merge conflicts` with link `Resolve conflicts...`; during an active resolve session the banner reads `Resolving merge conflicts is in progress` with links `Show resolve conflicts window` and `Cancel resolve`. | Open a conflicted file: the banner appears. |
| VCS-MERGE-004 | MUST | Changes-tree context actions for conflicted files (`Git.ChangesView.Conflicts`): `Merge` (`Git.ChangesView.Merge`), `Accept Yours` (`Git.ChangesView.AcceptYours`), `Accept Theirs` (`Git.ChangesView.AcceptTheirs`); progress `Resolving Conflict(s)`; loading `Loading merge conflicts...`. In the staging area tree the same exist as `Git.Stage.Merge`, `Git.Stage.AcceptYours`, `Git.Stage.AcceptTheirs`. Unresolved-state tab title `Conflicts`. | Right click a conflicted file: the three actions appear. |
| VCS-MERGE-005 | SHOULD | `Revert Resolved` (`Git.RevertResolved`; progress `Reverting resolved conflicts...`) returns files resolved during the current operation to the conflicted state; confirm `Revert Resolved Files` / `Do you want to revert resolved file(s): <paths>?`. | After accepting one side, Revert Resolved restores markers. |

## 2. Multiple-files conflicts dialog

| ID | Pri | Requirement | Acceptance |
|---|---|---|---|
| VCS-MERGE-010 | MUST | Dialog titled `Conflicts` with description `The following file has conflicts:` / `The following files have conflicts:` (plus the operation line from Git: `Merging branch <b> into branch <c>`, `Conflicts during cherry-picking commit <h> made by <a>`, `Rebasing branch <b> onto branch <t>`, `Rebasing onto diverging branches`, `Conflicts during <op> of commit ...`). Table columns: `Name` (with path), `Yours` / `Yours (<branch>)`, `Theirs` / `Theirs (<branch>)` (git status columns also show `Deleted`/`Modified`), optionally grouped by directory (checkbox `Group by directory`, default off). Buttons: `Accept Yours`, `Accept Theirs`, `Merge...`, with `Close` (Cancel) and in iterative mode `Accept and Finish`. | Dialog with 2 files shows both rows and the three buttons. |
| VCS-MERGE-011 | MUST | `Accept Yours` / `Accept Theirs` apply the full side to every selected file (rebase flips the meaning: in a rebase `Yours` is the branch being rebased onto, matching Git's ours/theirs swap; registry `git.do.not.swap.merge.conflict.sides` default false). They stage the result (`git add`) and remove the row; undo command names `Accept Yours`/`Accept Theirs`. `Merge...` opens the three-way viewer for one file (title `Merge Revisions for <file>`; loading `Loading merge revisions...`; errors `Error loading revisions to merge: <msg>`, `The file is too big to be loaded`, dialog title `Cannot Show Merge Dialog`). | Accept Theirs on a file: the working file equals the theirs content and the row disappears. |
| VCS-MERGE-012 | MUST | For binary or non-text conflicts the merge viewer shows a binary viewer with `Accept Left`/`Accept Right`; for delete/modify conflicts the dialog asks which side to keep (deleted side shows `Deleted`). | Delete/modify conflict: choices keep or delete. |
| VCS-MERGE-013 | SHOULD | Iterative resolution (registry `vcs.merge.conflict.iterative.resolution`, default **on**): the dialog tracks partial progress per file (column `<resolved>/<total>` tooltips `N change has been merged`), button `Resolve All Simple Conflicts` (tooltip `Apply all non-conflicting changes and resolve simple conflicts (ones that can be resolved through static analysis) across all files`; disabled tooltip `There are no simple conflicts to resolve`), result status `No conflicts were resolved automatically`, `All conflicts were resolved automatically`, `<n> conflicts resolved. <m> conflicts in <k> files still require attention`; row actions `Resolve Manually`, `Review Changes`, `Revert Conflict Resolution`, `Accept '<side>'`; confirmations `Overwrite Changes` (`This file already contains merged changes. Accepting changes from '<side>' will discard and overwrite them.`, `Discard and Accept`), `Confirm Revert` (`All changes will be reverted. The file will return to its original conflicted state.`), close confirmation `Discard Changes?` / `Closing the dialog will discard your changes in partially resolved files` (`Discard Changes` / `Continue Merge`); final `All conflicts have been resolved`. With registry `vcs.merge.conflict.file.suggestion` (default on) the next conflicting file opens automatically. | Resolve all simple conflicts on 3 files with 1 hard: status shows `2 conflicts resolved. 1 conflict in 1 file still requires attention`. |
| VCS-MERGE-014 | MUST | After the last file is resolved the dialog closes and the operation continues: merge asks nothing more (user commits, with the merge message prefilled), rebase asks `All conflicts have been resolved. Do you want to continue rebase?` (title `Resolve Conflicts`, action `Continue Rebase`), cherry-pick/unstash continue as configured. Leaving unresolved: notification `Pending Unresolved conflicts` / `There are pending unresolved conflicts.` | Resolve all in a rebase: prompt to continue. |

## 3. Three-way merge viewer

Layout: left pane (`Your version`), center pane (`Result`, the only editable pane, initially the
merged content with conflicts), right pane (`Changes from server`; Git names the sides
`Your version, branch <b>`, `Changes from <ref>`, `Changes from branch <b>`, `Changes from
diverging branches`, `Local Changes` / `Changes from cherry-pick <h>`, in a rebase
`Rebasing <b> from <r>` and `Already rebased commits`). Base is not shown but is used for diff
colors. Window title `Merge <file>`.

| ID | Pri | Requirement | Acceptance |
|---|---|---|---|
| VCS-MERGE-020 | MUST | Each change/conflict between the base and a side has gutter controls: accept (`>>`/`<<` arrows, action text `Accept`), ignore (`x`, `Ignore`), append (`Append`, shown with Ctrl/Shift), revert (`Revert`) and for conflicts `Resolve using Left`/`Resolve using Right`/`Resolve Automatically` (tooltip `Ctrl+click to resolve conflict`). Colors: inserted / changed / deleted / conflict (`Inserted`, `Changed`, `Deleted`, `Conflict` legend names), resolved changes render dimmed; modes (`Change Three-Side Viewer Mode`, `SwapThreeWayColorModeInDiffWindow`): `Left to right`, `Merge conflict`, `Resolved merge conflict`; options in the merge color dialog `Important`/`Ignored`. | Click `>>` on the left side of a conflict: the result takes the left text and the chunk becomes resolved. |
| VCS-MERGE-021 | MUST | Toolbar/menu: `Previous Difference` (`PreviousDiff`, `shift F7`), `Next Difference` (`NextDiff`, `F7`) (also `Previous Conflict` `Diff.PreviousConflict` / `Next Conflict` `Diff.NextConflict`: `Move to the previous/next unresolved conflict`), `Accept Left Side` (`Diff.ApplyLeftSide`, `Ctrl+Alt+R`), `Accept Right Side` (`Diff.ApplyRightSide`, `Ctrl+Alt+A`), `Append Left Side` (`Diff.AppendLeftSide`), `Append Right Side` (`Diff.AppendRightSide`), `Ignore Left Side` (`Diff.IgnoreLeftSide`), `Ignore Right Side` (`Diff.IgnoreRightSide`), `Resolve Automatically` (`Diff.ResolveConflict`), `Apply All Non-Conflicting Changes` (`Diff.ApplyNonConflicts`) with variants `Apply Non-Conflicting Changes from the Left Side` (`Diff.ApplyNonConflicts.Left`) / `...Right Side` (`Diff.ApplyNonConflicts.Right`) (toolbar popup `Apply non-conflicting changes:` with entries `Left`, `Right`, `All`), `Resolve Simple Conflicts` (`Diff.MagicResolveConflicts`), `Revert Conflict Resolution` (`Revert Conflict Resolution`, confirm title `Confirm Revert`, message `All changes will be reverted. The file will return to its original conflicted state.`, button `Revert`), `Compare Contents` group `Left and Middle` (`Diff.ComparePartial.Base.Left`), `Middle and Right` (`Diff.ComparePartial.Base.Right`), `Left and Right` (`Diff.ComparePartial.Left.Right`), `Base and Left` (`Diff.CompareWithBase.Left`), `Base and Middle` (`Diff.CompareWithBase.Result`), `Base and Right` (`Diff.CompareWithBase.Right`), `Resolve Conflicts in Import Statements` toggle (`Vcs.Diff.ResolveConflictsInImports`), highlight policy and ignore options (shared with the diff viewer), `Select Opposite Diff Pane` (`Diff.FocusOppositePane`, `Ctrl+Shift+Tab`). | Each action id is reachable from the toolbar or context menu. |
| VCS-MERGE-022 | MUST | Status line: `<n> changes, <m> conflicts` with forms `No changes`, `1 change`, `No conflicts`, `1 conflict`; when everything is resolved the green text `All conflicts resolved` (merge dialog message `All conflicts resolved`, `All changes have been processed`). Buttons: `Apply` / `Apply Changes` (default), `Cancel`, `Accept Left`, `Accept Right`; in the modal file-merge flow `Save and Finish` / `Continue` appear. | Resolve the last conflict: the status turns green. |
| VCS-MERGE-023 | MUST | Applying with unresolved items asks (title `Apply Changes`): `There is one change and one conflict left unprocessed.` followed by a line break and `Save changes and mark the conflict resolved anyway?`; plurals `There are N changes and M conflicts left unprocessed.`, `There is one conflict left unprocessed.`, `There are N changes left unprocessed.`; buttons `Apply Changes and Mark Resolved`, `Continue Merge`, `Cancel Merge` (also `Save and Finish` / `Continue` in the modal flow). Closing a modified merge window asks `Are you sure you want to exit without applying changes?` (title `Cancel File Merge`). The iterative variant (title `Unprocessed Changes`) reads `1 unresolved conflict and 2 unprocessed changes still remain. The file will be saved exactly as shown in the Result pane.` with buttons `Save Current Result` / `Back to Resolving`. | Click Apply with 1 unresolved conflict: `There is one conflict left unprocessed.` and the three buttons. |
| VCS-MERGE-024 | MUST | Setting (Settings > Tools > Diff & Merge > Merge): `Automatically apply non-conflicting changes` (`MERGE_AUTO_APPLY_NON_CONFLICTED_CHANGES`, default **off**), `Automatically resolve conflicts in import statements` (default **off**), `Highlight modified lines in gutter` (`MERGE_LST_GUTTER_MARKERS`, default **on**). When the first option is on the viewer applies all non-conflicting changes at open (undo name `Apply non-conflicting changes`). | Option on: opening a merge with 3 changes and 1 conflict leaves only the conflict. |
| VCS-MERGE-025 | MUST | Result undo/redo: each accept/ignore/resolve is one undo command with names `Accept change`, `Ignore change`, `Reset resolved change`, `Resolve conflict`, `Apply non-conflicting changes`, `Resolve simple conflicted changes`, `Revert conflict resolution`; typing in the result is allowed and recomputes the highlighting without disturbing resolved flags. | Accept then Ctrl+Z restores the unresolved chunk. |
| VCS-MERGE-026 | MUST | The result file is only written when the user applies; the original conflicted content can be restored when the underlying conflict is outdated: `Merge conflict is outdated. Restore file content prior to conflict resolve start?` Read-only result: `Cannot resolve conflicts in a read-only file`. Invalid conflict: `Conflict is not valid and no longer can be resolved.` with `Abort Resolve`. | Modify the file externally during merge: the outdated prompt appears. |
| VCS-MERGE-027 | SHOULD | External merge tool: with `Merge In External Tool` the IDE writes temp files and shows `Launching External Tool...` / `Waiting for External Tool...` / `Press "Mark as Resolved" when you finish resolving conflicts in the external tool` and the button `Mark as Resolved`; configuration in Settings > Tools > Diff & Merge > External Diff Tools (see VCS-DIFF-070). | External tool exit code 0 with `Trust process exit code` marks resolved. |

## 4. Automatic resolution

| ID | Pri | Requirement | Acceptance |
|---|---|---|---|
| VCS-MERGE-030 | MUST | A non-conflicting change is one where only one side differs from the base; applying it takes that side. A conflict is a region where both sides differ from the base and from each other. | Left changes line 1, right changes line 9: both are non-conflicts. |
| VCS-MERGE-031 | MUST | `Resolve Simple Conflicts` resolves conflicts by a word-level three-way merge (first with exact comparison, then ignoring whitespace): a conflict is resolved when, inside it, no word range is changed differently by both sides (identical edits by both sides, or an edit on one side plus a whitespace-only edit on the other, count as resolvable); the merged text takes the changed side per range. Failure (too big a diff or true overlap) leaves the conflict. | Left `a b c`, base `a b c`, right changed identical to left: resolved. Left changes word 1, right changes word 3 on the same line: resolved to both edits. |
| VCS-MERGE-032 | SHOULD | Semantic resolution (registry `semantic.merge.conflict.resolution` default true; `semantic.merge.recompute.after.change` default true): language plugins may resolve conflicts from structure; import-statement conflicts resolve via `Resolve Conflicts in Import Statements`. | Two sides adding different imports resolve into the union. |
| VCS-MERGE-033 | LATER | AI-assisted resolution (changes flagged resolved-with-AI) is not specified. | Not scheduled. |
