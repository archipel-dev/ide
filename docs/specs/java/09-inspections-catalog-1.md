# 09. Java inspections catalog, part 1

Status: specification, clean-room. Written from the IntelliJ IDEA Community sources in our own words. Message
templates, option labels and fix names are quoted from the message bundles (short user-visible strings). Source
paths are cited as `ic: <path>`. No code is reproduced.

This file and its two siblings (`09-inspections-catalog-2.md`, `09-inspections-catalog-3.md`; further parts are
written by other agents) complete the inspection coverage that `07-inspections.md` (the 40 most used,
`JAVA-INS-*`) starts. Part 1 covers the inventory file `inventory/inspections-java-1.md`: Cast, Class, Code
(plugin development), Description file, Embedded, Gradle and JUnit groups. The framework (severity levels,
profiles, suppression, batch run, cleanup) is in `codeinsight/03-inspections.md` (`CI-INS`); this catalog only
states what is specific to each inspection.

Primary sources: `ic: java/java-backend/resources/META-INF/InspectionGadgets.xml` (registration: short name,
group, default state, level), `ic: java/java-analysis-impl/resources/messages/InspectionGadgetsBundle.properties`,
`ic: java/java-analysis-impl/resources/inspectionDescriptions/*.html`, the inspection classes under
`ic: java/java-analysis-impl/src/com/siyeh/ig/` and `ic: java/java-impl/src/com/siyeh/ig/`,
`ic: plugins/junit/` (resources, messages and tests), `ic: plugins/devkit/devkit-core/`.

## 9.1 How to read the tables

- **Short name** cell: the short name (suppression id, profile key), the display name, `on`/`off` (enabled by
  default), the default severity and, when it applies, `global (batch run only)` and `cleanup-eligible`
  (the inspection takes part in *Code | Code Cleanup* and fixes can be applied file-wide).
- **Behavior** cell: `Reports` (the trigger conditions), `Does not report` (the important exceptions),
  `Range` (what is highlighted; "the name" means the name identifier), `Message` (templates; `#ref` is the text
  of the highlighted element, `{0}` etc. are filled arguments), `Options` (label and default), `Quick fixes`
  (exact names as shown in the Alt+Enter popup, with what they do).
- **Priority:** enabled-by-default inspections of supported technology are `MUST`; inspections that are off by
  default are `SHOULD`; inspections of obsolete or out-of-scope technology are `LATER` with the reason stated
  in the row (no cases required).
- Severity `Information` means no marker in the editor; the fix is then available through Alt+Enter only.
- Cases are in `cases/09-inspections-1.cases.md`. Keys `inspect` mean: run the inspection on the file; the
  `problem:` lines list the expected highlights as `level range "message"`. `settings:` lists non-default
  inspection options (by their labels) and project setup (`library=` names the test libraries on the classpath,
  `language level=` the module language level).
- Quick fixes of naming inspections (`Rename`) start the in-place rename refactoring and are offered only in the
  editor, never in batch runs.

## 9.2 Requirements

Each inspection is one requirement. Acceptance is the set of executable cases named in its row: the default
state and level, the message text, the highlighted range and the effect of each listed fix must match.
