## 1. Selecting what to extract

| ID | Pri | Requirement | Acceptance |
|---|---|---|---|
| REF-EXT-001 | MUST | **Introduce Variable without a selection.** The handler computes candidate expressions around the caret. (a) If the line of the caret holds exactly one statement and the caret is outside the expression part of that statement (before it, after it, or on its trailing whitespace), the *whole expression of that line* is selected (the selection is the full line) and used directly; the same applies when the registry/user option "prefer statements" is on. (b) Otherwise all expressions that contain the caret position are collected (innermost first, then enclosing ones, up to but excluding expression statements) and filtered to those that have an enclosing statement or field initializer. (c) If none: the error `Selected block should represent an expression`; (Ctrl+Alt+V on a line with no extractable expression while an in-place introduce session exists switches to the *reassign* mode of REF-EXT-007). (d) If exactly one distinct candidate: it is used. (e) If several: the expression chooser (REF-EXT-002). With a selection, the selected text must form one expression (`Selected block should represent an expression`) or a statement that holds one. | Cases REF-EXT-001 case 1-3. |
| REF-EXT-002 | MUST | Expression chooser: a small list popup titled `Expressions` at the caret, one row per candidate expression showing its text shortened in the middle (trimmed rendering of the expression), innermost first; moving the selection highlights the candidate in the editor (selection-like highlight of the expression range); `Enter` picks, `Esc` closes. The preselected row is the first, except when the first candidate is a reference to a local variable: then the second row is preselected. | Case REF-EXT-002 case 1. |
| REF-EXT-003 | MUST | **Occurrences.** All expressions in the enclosing scope (method body, lambda, initializer; the class for fields) that are structurally equal to the chosen one *and* have the same resolved meaning are occurrences (equality ignores whitespace and redundant parentheses; calls to a method with a different resolved target do not match). If there is more than one, the occurrences chooser pops up (title `Multiple occurrences found`; `Lambda chain detected` for lambda chains). Rows, in this order, when applicable: (1) `Replace this occurrence only`; (2) `Replace all occurrences but write` (only when some occurrences are assignment targets and the chosen one is a read; replaces the reads); (3) scope rows `Replace {n} occurrences in{ outer} '{keyword}' block` (up to two per keyword, keyword one of `if`, `if-then`, `else`, `while`, `for`, `for-each`, `do-while`, `try`, `lambda`; only when occurrences group by different blocks) (4) `Replace all {N} occurrences`; when write accesses are present the last row reads `Replace read and write occurrences (will change semantics!)` (or `Replace all {N} occurrences (will change semantics!)` when no occurrence is a pure read); it is omitted when replacing all is impossible (a final variable is assigned). Lambda-chain variants: `Replace all {N} occurrences and extract as '{name}' operation`, `Create variable inside current lambda`, `Extract as '{name}' operation`. Choosing a row highlights its occurrences with the search-result highlight; `Enter` picks. With exactly one occurrence the chooser is skipped. | Cases REF-EXT-003 case 1-3. |
| REF-EXT-004 | MUST | Introduce Variable error texts (editor hint with first line `Cannot perform refactoring.`): `Selected block should represent an expression`, `Selected expression has type 'void'`, `Unknown expression type.`, `Selected expression cannot be extracted`, `Introduce Variable refactoring is not supported in the current context`, `Cannot extract variable in an interface.`, `Cannot extract in a compact source file.`, `Selected expression introduces pattern variable '{0}'`, `The selected expression refers to pattern variable '{0}', which will be out of scope.`, `Extracting the selected expression changes the semantics of the surrounding expression.`, `Enum constant in switch label cannot be extracted`, `Invalid expression context.` (declaration would precede `this(...)`/`super(...)`), `No matching occurrences`. | Case REF-EXT-004 case 1,2. |

### 1.1 Introduce Variable (Java)

| ID | Pri | Requirement | Acceptance |
|---|---|---|---|
| REF-EXT-005 | MUST | In-place form (default). After the occurrence choice the declaration `Type name = expr;` is inserted at the **anchor** (REF-EXT-006), the chosen occurrences are replaced by `name`, and a template session starts on the *name* (the whole name selected). Lookup: type-based/name-based suggestions (REF-EXT-010). `Enter` accepts, `Esc` cancels (REF-FRM-052: declaration removed, expression restored). `Tab` opens the options popup with: checkbox `Declare final` (not shown when the variable cannot be final, e.g. replace-all with write accesses) and, only when the expression's type is denotable and the language level has `var`, `Declare var type`; both reflect and persist the settings `final locals` (default: the code style's `Generate final locals`, off) and `var type` (default off) and rewrite the declaration immediately. The advertisement line in the lookup: `Press {shortcut of Introduce Variable} to reassign existing variable` when a variable of the same type is visible, else `Press Shift+Tab to change type` when several types are possible. | Case REF-EXT-005 case 1,2. |
| REF-EXT-006 | MUST | Anchor and shape of the result: the declaration goes right before the statement that holds the (first replaced) occurrence; with replace-all it goes before the statement holding the *first* occurrence in the common ancestor block. Special statements: expression of an `if`/`while`/`for` condition: the declaration goes before the statement; for a `for` loop condition (not `while`) whose variables are modified in the loop the refactoring reports `{Variable description} is modified in loop body` (first letter capitalized, one line per variable, for example `Local variable i is modified in loop body`) and `Introducing variable may break code logic` as the error hint (in-place mode) or as the conflicts dialog (dialog mode); expression-bodied lambda: the body is converted to a block `{ Type name = expr; return name; }` (or an expression statement for void lambdas); a `switch` rule `case X -> expr`: converted to a block; in a `for` init: before the loop; a statement body without braces (`if (x) foo(e);`) is wrapped into braces; `else if`: handled by wrapping. The initializer is the expression text (diamond collapsed where possible, redundant casts removed). If the occurrence is the whole expression statement `expr;` the statement itself becomes the declaration. | Cases REF-EXT-006 case 1-4. |
| REF-EXT-007 | MUST | Type and reassign: when several types fit (the expression's type and its supertypes/interfaces which are valid for all selected occurrences) the first template stop is a type field before the name; the user reaches it with `Shift+Tab` and picks a type from a lookup (default: the expression's own type; for diamonds/anonymous classes the denotable supertype). | REF-EXT-008 | MUST | Replace-all semantics: with every occurrence read-only, all become the variable; `Replace all occurrences but write` leaves assignment targets untouched; `Replace read and write occurrences` replaces assignment targets too (the variable is then non-final and the semantics change). The declaration becomes `final` automatically when replace-all is chosen and the occurrences are used in a final context (lambdas/anonymous classes), and when the user setting `Declare final` is on. | Case REF-EXT-008 case 1. |
| REF-EXT-009 | MUST | Lambda target block chooser: when the chosen expression sits in an expression lambda and does not depend on the lambda's parameters, a popup titled `Select Target Code Block` offers the places to declare the variable: the first row `Containing block` (outside, above the whole statement that holds the lambda) and one row per enclosing lambda in the form `{FunctionalInterface}: {lambda text}` (declaring inside that lambda). Selecting a row highlights the target range. An expression that uses a lambda parameter offers only the lambda itself. | Case REF-EXT-009 case 1. |
| REF-EXT-010 | MUST | Name suggestions (first = initial name), from the code style (`Settings | Editor | Code Style | Java | Code Generation` name prefixes/suffixes apply to the `local variable` kind): (1) from the expression: a method call `getX()`/`isX()`/`hasX()` gives `x`; `new Foo(...)` gives `foo`; a field/variable reference gives its name; a call `list.size()` gives `size`; a string literal gives names derived from its words (`"hello world"` gives `helloWorld`) when short; (2) from the type: collections of `Foo` give `foos`, `String` gives `s`/`str`, `int` gives `i`, arrays pluralize the element name, boxed types the primitive's; (3) unique among variables visible at the anchor (a numeric suffix is appended when needed); the lookup lists all suggestions; the entered name is validated as a Java identifier and unique in the scope (error `Name clashes with existing variable` / `Incorrect name` / `This name is already used` in the dialog form). | Cases REF-EXT-010 case 1-3. |
| REF-EXT-011 | SHOULD | Dialog form (`In modal dialogs`): `Introduce Variable` dialog with: label `Name:` (combo with suggestions), `Variable of type:` type selector, checkboxes `Declare final`, `Declare var type` where applicable, `Replace all occurrences ({N} occurrences)` (shown when more than one occurrence), buttons `OK`/`Cancel`; shows the conflicts dialog for `Introducing variable may break code logic`. | Switch to modal dialogs: dialog appears. |
| REF-EXT-012 | MUST | After the refactoring the replaced occurrences are highlighted and the status bar shows `Press Escape to remove the highlighting` (Escape removes the highlighting). | Perform Introduce Variable with replace-all: occurrences highlighted. |

## 5. Extract Method (Java)

Flow: select statements or an expression (`Ctrl+Alt+M`). Without a selection: the expressions at the
caret are collected; none: the line at the caret is selected; one: it is used; several: the
expression chooser (REF-EXT-002); then the selection decides. With a selection the *extractable
elements* are computed: a single expression, or the statements fully contained in the selection
(a partial statement selection is rounded to whole statements; selecting only part of a statement
that is an expression is accepted as the expression).

| ID | Pri | Requirement | Acceptance |
|---|---|---|---|
| REF-EXT-050 | MUST | In-place form: the extracted method is inserted into the target class right **after the method that contains the extracted code** (with one blank line), and the selection is replaced by the call; a template session starts with the *method name* selected, linked between the declaration and the call; below the call a lookup lists name suggestions; `Enter` finishes, `Esc` cancels (code restored). A small inlay/popup (`Tab`) offers `Annotate` (nullability annotations on the return/parameters when determinable and annotations are configured), `Make static` or `Make static and pass fields` (when possible and not already static) and a link `More options` that opens the dialog form (REF-EXT-053). A preview of the new method is shown in a floating code preview next to the editor. Visibility of the new method: `private`; static when the surrounding context requires it (the method is in a static context or the code uses no instance state and `Make static` is ticked). | Cases REF-EXT-050 case 1-3. |
| REF-EXT-051 | MUST | Method name suggestions in order: (1) if the element before the selection is a comment shorter than 20 characters after camel-casing, the comment's words in camelCase (`// print total` gives `printTotal`); (2) for a single output variable: `create`+Name when the variable is declared in the selection with a `new` initializer, `is`+Name for boolean, else `get`+Name, with names from the code style's field-name suggestions; (3) for an expression result of non-primitive/non-void type: `create`/`is`/`get` + type-based name; for a method call expression the call's own derived names; (4) when nothing is suggested: `extracted`. Names that conflict with an existing method of the same signature in the target class are skipped; when all conflict, `extracted`, `extracted1`, `extracted2`... | Cases REF-EXT-051 case 1-3. |
| REF-EXT-052 | MUST | Analysis rules. **Parameters**: every local variable/parameter read in the selection and declared before it becomes a parameter, in order of first use; `this`-bound instance members are used directly (they stay instance state; forced static passes the used fields as parameters); a variable written in the selection and read afterwards is an **output**: with exactly one output it is returned (`return x;` appended and the call becomes `T x = name(...)` or an assignment when the variable was declared before the selection); with several outputs see REF-EXT-054. Local variables only used inside stay local. **Exit points**: `return` statements in the selection: supported shapes: every path of the selection returns (the call becomes `return name(...);`), no path returns, or `return`/`break`/`continue` leave the fragment conditionally (the new method returns a boolean flag and the call site becomes `if (name(...)) return/break/continue ...;`); other combinations produce `There are multiple exit points.` **Exceptions**: checked exceptions thrown in the selection are added to the `throws` clause of the new method. **Type parameters** used in the code are carried into the signature. **Static context**: code in a static method yields a static method. **Final fields**: assigning a final field gives `There is an assignment to the final field.` Local classes: `Local class is used out of the selected block.`, `Local class is defined out of the selected block.`. Others: `Selected block should represent a set of statements or an expression`, `Selected block contains invocation of another class constructor`, `Selected block contains a statement outside a class`, `Code contains syntax errors. Cannot perform necessary analysis.`, `Selected block should be a part of java class.`, `Unable to extract method from annotation value`, `Cannot extract method because the selected code fragment uses local classes defined outside of the fragment`, `... defines local classes used outside of the fragment`, `... defines variable of local class type used outside of the fragment`, `There is a variable to return inside of the selected expression.`, `It would behave differently when an exception is thrown.`. All errors are shown as an editor hint prefixed `Unable to extract method.` and the offending code is highlighted (`Press Escape to remove the highlighting` in the status bar). | Cases REF-EXT-052 case 1-5. |
| REF-EXT-053 | MUST | Dialog form (`More options` / modal-dialog setting): `Extract Method` dialog with: `Method name:`, visibility selector (`public`, `protected`, `package-private`, `private`; default `private`), `Declare static` / `Make static` (and pass fields), `Declare varargs` when the last parameter is an array, `Declare final`-style annotation checkbox `Annotate` where applicable, `Extract chained constructor` for code at the start of a constructor, a table of `Parameters` (include/exclude check, type editable, name editable, up/down reordering with `Alt+Up/Down`, a `Pass` column for folded parameters), the list `Output variables`, a read-only `Signature preview` text, and the line `{N} duplicate code fragment(s) can be replaced with the extracted method call` when duplicates exist (`Searching for duplicates...` first). Buttons: `OK`, `Cancel`, `Preview`. Validation: an invalid method name, parameter name clash `Conflicting parameter name: {0}`, `Variable with name {0} is already defined in the selected scope`, `Method with the same signature already exists`. | |
| REF-EXT-054 | MUST | Several output variables: when the selection writes more than one variable that is used afterwards, Java first introduces a **result object**: a record (language level 16+) or a class, wrapping the variables, with a template session to name it; the hint `There are several output variables in the selected code block.\n The method can be extracted if we fold them into a new record.` (or `a single object`) is shown; after finishing that session Extract Method runs on the rewritten code. If the variables cannot be folded: `There are multiple variables to return.`; the old dialog form message `There are multiple output values for the selected code fragment:` + list. | Case REF-EXT-054 case 1. |
| REF-EXT-055 | MUST | Duplicates: code fragments in the *target class* that are equal to the extracted code up to renaming of variables that become parameters and constants that can become parameters are detected; after the extraction (Enter) they are replaced by calls to the new method in the same command (no extra dialog in in-place mode); the status/hint reports the count; in dialog form the dialog line of REF-EXT-053 and, after OK, the question `{ProductName} has detected {N} code fragment(s) in this file that can be replaced with a call to extracted method. Would you like to review and replace them?` with `Yes`/`No` where Yes opens the preview `Extract Method from Duplicate Code`. If replacing needs a signature change: `In order to replace all occurrences method signature will be changed. Proceed?`. | Case REF-EXT-055 case 1. |
| REF-EXT-056 | SHOULD | Target class choice: when the code is inside an anonymous/local/inner class, the list of possible target classes (innermost first, e.g. the anonymous class, the enclosing class) is offered in a popup before the template; the default is the nearest named class. | |
| REF-EXT-057 | SHOULD | Extract Method Object (`Replace Method With Method Object...`, `Extract Method Object`), Extract Delegate, Introduce Parameter Object, Introduce Functional Parameter/Variable and Extract Include: see REF-EXT-080..090 (LATER/SHOULD). | |
