## 1. Git stash

| ID | Pri | Requirement | Acceptance |
|---|---|---|---|
| VCS-STASH-001 | MUST | `Stash Changes...` (`Git.Stash`; menu Git > Uncommitted Changes > Stash Changes...) opens dialog `Stash` (title `Stash`, button `Create Stash`): root chooser when several (`Git Root:` mnemonic R), `Message:` (tooltip `Enter stash message here`), `Keep index` (tooltip `If this checkbox is selected, all changes already added to the index are left intact`), `Include untracked` (tooltip `If this checkbox is selected, all untracked files are also stashed`). Progress `Stashing changes from '<root>'...`; error `Failed to stash <root>` / `Cannot stash <root>: <msg>`; unavailable: `Cannot Stash Changes Now`. | Dialog fields appear in that order; Create Stash runs `git stash push`. |
| VCS-STASH-002 | MUST | `Stash Silently` (`Git.Stash.Silently`, staging area toolbar) and `Stash Files` (`Git.Stage.Stash.Files`) stash without a dialog; success `Files stashed successfully` / `Files in <root> stashed successfully` with links `View Git stashes` or `Enable and view Git stashes`; progress `Stashing Files`; failure `Failed to Stash Files`. If the index holds other staged changes they are saved too and a notification `Staging area in <root> contains modifications to other files that were saved to the stash` with action `Don't show again`. | Stash Silently with one modified file: the file reverts and a stash entry appears. |
| VCS-STASH-003 | MUST | `Unstash Changes...` (`Git.Unstash`) opens dialog `Unstash Changes` (`Unstash Changes in <root>`): `Current branch:` label, `Stashes:` list, buttons `View` (tooltip `View selected stash`, dialog `Paths Affected by <stash>`), `Drop` (tooltip `Delete selected stash`), `Clear` (tooltip `Delete all stashes in the repository`), checkboxes `Pop stash` (tooltip `If selected the stash is dropped after it is applied`), `Reinstate index` (tooltip `Attempt to reinstate index as well as working tree changes`), field `As new branch:` (tooltip `If non-empty name is entered, the stash is checked out as a new branch`); action button text `Apply Stash` / `Pop Stash` / `Branch` according to the options. Confirmations: `Remove all stashes? This cannot be undone.` (title `Remove All Stashes?`), `Do you want to remove <stash>?<br/>"<message>"` (title `Remove Stash <name>?`). Results: `Stash successfully applied`, `Unstashed with conflicts`, `Unstash failed`, `Unstash failed due to an index conflict`; with conflicts the conflict dialog `Conflicts during unstashing <name>` (left `Local changes`, right `Changes from stash`) and notification `Local changes were restored with conflicts` / `Your uncommitted changes were saved to stash.<br/>Unstash is not complete, you have unresolved merges in your working tree<br/>Resolve conflicts and drop the stash.` | Apply a stash onto a clean tree: the files reappear and the stash stays. |
| VCS-STASH-004 | MUST | Stash tool window tab: tab `Stash` (or `Stashes and Shelves` when `Combine stashes and shelves in one tab` is on, default off; registry `git.enable.stash.toolwindow` default on); tree root node `Stashes`; empty text `No stashes or shelves added.` with help link `Getting started with Stash and Shelf`; detail pane placeholder `Select stash or shelf to view files`, `Loading...`. Context menu (`Git.Stash.Operations.ContextMenu`): `Pop` (`Git.Stash.Pop`, mnemonic P), `Apply` (`Git.Stash.Apply`, A), `Unstash...` (`Git.Stash.UnstashAs`, U; `Pop or apply selected stash as new branch with or without index`), `Drop` (`Git.Stash.Drop`, D, `Delete` key), `Clear` (`Git.Stash.Clear`, C; per root `Clear Stashes in <root>`), plus `Compare with Local`, `Show Diff`, and in the changes browser `Compare Before with Local`, `Edit Source`, `Open Repository Version`, `Cherry-Pick Selected Changes`. Toolbar: `Refresh Stashes` (`Git.Stash.Refresh`), `Preview Diff` toggle (`Git.Stash.Toggle.Split.Preview`; setting default on). `Show Git Stash` (`Git.Show.Stash`) / `Show Stashes and Shelves` (`Git.Show.Stash.With.Shelf`) open it. The diff of a stash compares with the local version by default (`When "Show Diff" is called, compare stashed changes:` `With the local version of a file` default, or `With the parent commit`). Apply/Pop tooltips `Apply — apply and keep the stash in the list. Pop — apply and remove the stash from the list.` Created-on tooltip `<name> created on <date> at <time>`. | Right click a stash: the five operations appear in that order. |
| VCS-STASH-005 | MUST | Stash entries are named by Git (`stash@{n}`) with the subject `WIP on <branch>: <hash> <subject>` or the user message; the list is ordered newest first; entries created by the IDE around an operation have the message `Uncommitted changes before <operation>` (with ` at <time>` variant). | After Update with the stash policy, a stash `Uncommitted changes before Update` exists until restored. |
| VCS-STASH-006 | SHOULD | Save policy for update/checkout/rebase (`Clean working tree using:`): `Stash` or `Shelve` (default Shelve). The IDE restores the saved changes automatically; if restoring conflicts it opens the conflict dialog (`Uncommitted changes that were saved before <op> have conflicts with files from <ref>`; left titles `Uncommitted changes from the shelf` / `...from the stash`, right `Changes from <ref>`) and keeps the saved copy. | Dirty update with conflicts keeps the saved copy and shows the dialog. |

## 2. Shelf

The shelf stores local changes as patches (plus optional base content) outside the working tree.

| ID | Pri | Requirement | Acceptance |
|---|---|---|---|
| VCS-SHELF-001 | MUST | `Shelve Changes...` (`ChangesView.Shelve`; menu Git > Uncommitted Changes > Shelve Changes...) shelves the selected changes (or the active changelist) into a shelved changelist named from the changelist (a dialog lets the user edit the name); the shelved files are reverted in the working tree (rolled back) unless the `Save To Shelf` variant (`ChangesView.SaveToShelve`, copies without rollback) is used. `Shelve Silently` (`ChangesView.ShelveSilently`, `Ctrl+Shift+H`) does it immediately with an auto-generated name. Progress `Shelving changes...`; success `Changes shelved successfully`; failure `Shelving changes failed: <msg>` / `Shelving failed`; guard `The selected changes affect only directories and no files, so they cannot be shelved`; locked file message `The file is locked for editing while being shelved`. | Shelve a modified file: the working file reverts and the Shelf lists it. |
| VCS-SHELF-002 | MUST | The Shelf tab (`Shelf`; `Show Shelf` `Vcs.Show.Shelf`) lists shelved changelists under the root node `Shelves`, newest first, each with name, date, files; `Recently Deleted` node (restorable with `Restore` / `Restore Applied Shelved Change` `ShelvedChanges.Restore`, description `Restore recently deleted changelist(s)`). Toolbar: `Unshelve Silently` (`ChangesView.UnshelveSilently`, `Ctrl+Alt+U`), `Show Diff`, `View Options` (`Group By`, `Show/Hide Applied Shelved Changes` `ShelvedChanges.ShowHideDeleted` labelled `Already Unshelved`), `Expand All`, `Collapse All`. Context menu: `Unshelve...` (`ShelveChanges.UnshelveWithDialog`, `Ctrl+Shift+U`), `Restore`, `Show Diff`, `Show Diff in a New Tab or Window`, `Compare with Local` (`Vcs.ShowDiffWithLocal`), `Create Patch...`, `Copy as Patch to Clipboard`, `Import Patches...` (`ShelvedChanges.ImportPatches`), `Rename...` (`ShelvedChanges.Rename`, `F2`/`Shift+F6`), `Delete`. Combined list actions when stashes/shelves share a tab: `Apply` (`Vcs.Shelf.Apply`), `Pop` (`Vcs.Shelf.Pop`, `Pop selected shelf`), `Drop` (`Vcs.Shelf.Drop`, text `Delete`, `Delete selected shelf`), `Unshelve` (`Vcs.Shelf.UnshelveChanges`), `Unshelve and Remove` (`Vcs.Shelf.UnshelveChangesAndRemove`). Tree accessible name `Shelves`. | Context menu order matches. |
| VCS-SHELF-003 | MUST | `Unshelve...` dialog `Unshelve Changes`: shows the files with target paths (editable via `Correct paths where to apply patches and unshelve`), target changelist chooser (`Unshelve Changes to Changelist`), checkbox `Remove successfully applied files from the shelf`; `Unshelve Silently` applies to the original changelist. Result: when the patch no longer applies the conflict merge dialog opens with titles `Local version`, `Merge result`, `Shelved version`; failures `Cannot load patch(es): <msg>`, `Cannot fully restore shelved changelist as some files were deleted permanently`, base-content hint `Base content not found or not applicable. Showing difference with local version`. Progress `Unshelving changes...`. | Unshelve a clean shelf: files return to the changelist. |
| VCS-SHELF-004 | MUST | Delete: removing a changelist from the shelf moves it to `Recently Deleted`; notification `<n files> and/or <the 'x' changelist> deleted from shelf successfully` with action `Undo Shelf Deletion`; after unshelving with the removal checkbox the changelist is marked already-unshelved. Setting `Delete already unshelved changelists:` (retention). | Delete then Undo restores the entry. |
| VCS-SHELF-005 | SHOULD | Rename dialog (`Rename...`, field prefilled); name uniqueness not enforced, empty rejected. Import: `Import Patches...` picks patch files (prompts `Found one patch file (<f>). Continue with import?` / `Found N patch files. Continue with import?`; progress `Import Patch to Shelf`, error `No patches found`) into new shelved changelists. | Import a `.patch`: a shelved changelist appears with its files. |
| VCS-SHELF-006 | SHOULD | Settings: shelf location (`Change Shelves Location...` dialog `Change Shelves Location`, `Store shelves in:` with `Default directory:` (default `<project root>/.idea/shelf`) and `Custom directory:`, validation `Destination shelf directory must have the write access`, `...read access`, `Cannot find or create a new shelf directory`; `Move shelves to the new location` checkbox default off, progress `Copying Shelves to the New Directory...`; failure prompt `Shelves moving failed.` with `Use New` / `Revert`), `Shelve base revisions of files under distributed version control systems` (`INCLUDE_TEXT_INTO_SHELF`, default on; note `The base content of files larger than <n>K will not be stored`). | Defaults as listed. |
| VCS-SHELF-007 | MUST | A shelved changelist record holds: name, creation date, list of changes (path before and after, change type, the textual patch or full content for added and binary files, optional base content), a `recycled` flag (already unshelved) and a `deleted` flag (in `Recently Deleted`). The on-disk layout (one patch file per changelist plus metadata) is an implementation detail to be confirmed in OQ-1; only behavior in this file is required. | Shelve, restart, unshelve: the content round-trips. |
| VCS-SHELF-008 | LATER | AI-generated shelf titles (registry `llm.vcs.shelve.title.generation`). | Not scheduled. |

## 3. Patches

| ID | Pri | Requirement | Acceptance |
|---|---|---|---|
| VCS-PATCH-001 | MUST | `Create Patch from Local Changes...` (`ChangesView.CreatePatch`, menu Git > Patch; `Create Patch...` for committed/shelved changes `ChangesView.CreatePatchFromChanges`) opens `Create Patch` (settings dialog title `Patch File Settings`) with `To file:` (default extension from last use: `patch`, or `diff` if the last created patch used `.diff`), `To clipboard:`, `Base path:`, `Encoding:`, `Reverse patch`; errors `Base path cannot be empty!`, `Base dir doesn't exist`, `Base path doesn't contain all selected changes (use <path>)`, `File path should not be too long.`, `Cannot write patch to specified file: <f>`, binary: patches carry binaries as encoded blocks. Success: confirmation `Successfully created patch <file>`; the setting `When patch is created:` (`Ask` / `Show in <file manager>` / `Do nothing`). `Copy as Patch to Clipboard` (`ChangesView.CreatePatchToClipboard`) yields `Patch copied to clipboard`. Context lines count is 3 (registry `patch.context.line.count`). | Create a patch of one modified file: the file contains a unified diff with 3 context lines. |
| VCS-PATCH-002 | MUST | `Apply Patch...` / `Apply Patch from Clipboard...` (`ChangesView.ApplyPatch`, `ChangesView.ApplyPatchFromClipboard`): dialog `Apply Patch` with `Patch file name:`, a table of files (Before/After, status `Modified`, `Deleted`, `Added`), base-path correction (`Map Base Directory...`, `Select base directory for a path`, `missing base`), target changelist, option `Reverse patch`; clipboard variant `Analyze and apply patch from clipboard on the fly` (`DETECT_PATCH_ON_THE_FLY` off). Result texts: `Patch successfully applied`, `All changes in the specified patch are already contained in the code`, `Some of the changes in the specified patch were skipped because they are already contained in the code`, conflicts open `Patch Conflict for <file>` with `Local version`, `Merge result`, `Patched version`, `Patch`; failures: `Cannot find patch file <f>`, `Selected file <f> is not patch type file`, `Content is not a patch`, `Clipboard content is not a patch`, `Cannot apply file <f> from patch because it is binary.`, `File to patch found outside content root: <p>`, `Overwrite Existing Files` prompt `The following file should be created by patch, but it already exists. Do you want to overwrite it?`; partial failure dialog `Patch Applying Partly Failed` with rollback offer `Failed to apply patch to file(s):` / `Other changes from the patch have been applied successfully, would you like to rollback them?` (`Rollback`, `Abort...`, `_Abort and Rollback`, `_Skip`). Rolling back after abort: `All files changed during 'Apply Patch' action were rolled back`. | Apply a valid patch: changes appear in the active changelist. |
| VCS-PATCH-003 | SHOULD | Patch parser error messages: `Invalid patch file: <reason>`, `Patch file is empty`, `Binary patch file`, `Could not parse the patch file`, `Unknown line prefix`, `Cannot detect file names from git format header line`, plus the simple-apply mismatch details (`Unexpected baseline: expected - <a>, actual - <b>` etc.). | A truncated patch reports the first matching message. |
| VCS-PATCH-004 | MUST | `Rollback...` (`ChangesView.Revert`, `Ctrl+Alt+Z`; `ChangesView.RevertFiles` for files) shows dialog `Rollback Changes` listing the selection with checkbox `Delete local copies of added files`; the operation restores base content (`Rolling back <path>`), progress `<VCS>: performing rollback...`; added files are unversioned afterwards (or deleted when the checkbox is on). With the staging area: `Rollback` (`Git.Stage.Revert`). | Rollback a modified file: contents return to HEAD and `Ctrl+Z` in the editor is not required. |
