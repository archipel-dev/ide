## 4. Cherry-pick, revert, reset, undo

| ID | Pri | Requirement | Acceptance |
|---|---|---|---|
| VCS-LOG-030 | MUST | `Cherry-Pick` (`Vcs.CherryPick`; log toolbar, log and file-history context menus; text `Cherry-Pick`) applies the selected commits (oldest first) to the current branch with `git cherry-pick`. Disabled when commits belong to different VCSes (`Selected commits are tracked by different vcses`), the commit is a merge, or a cherry-pick is already running (`Cherry-pick process is already started for commit <h> from root <r>`), or not supported (`Cherry-pick is not supported for commit <h> from root <r>`). Progress `Cherry-Picking '<subject>' (<i>/<n>)`. Suffix `(cherry picked from commit <hash>)` is added only when the source commit is on a protected branch and the setting `Add the 'cherry-picked from <hash>' suffix...` is on (default on). Empty commits follow `On empty cherry-pick commit:` Skip (default) / Create empty commit; skipped notice `<n> commit(s) was/were skipped, because all changes have already been applied.` | Cherry-pick a commit of another branch: a new commit with the same subject on HEAD. |
| VCS-LOG-031 | MUST | Operation outcome texts (operation names `cherry-pick`/`revert`): `<Op> successful` with `Cherry-picked 1 commit from <hash>`-style details (`<Op> <n> commit(s) from <source>`), `Nothing to <op>`, `<Op> canceled`, `<Op> failed`, `<Op> was performed with conflicts`, `There are unresolved conflicts in the working tree.` with actions `Resolve...` and `Abort <op>`; the conflict dialog header `Conflicts during cherry-picking commit <h> made by <author>`; local changes in the way: `Your local changes will be overwritten by <op>. Commit, <save>, or revert them to proceed.` with `View them`; `Save Changes and Retry` (`<Op> Changes and Retry`); `Local changes were saved before <op>` with `Restore local changes`. A successful commit sequence finishes with the commit dialog prefilled with the original message when changes are not auto-committed. | Cherry-pick with conflict: notification includes `Resolve...` and `Abort Cherry-Pick`. |
| VCS-LOG-032 | MUST | `Revert Commit` (`Git.Revert.In.Log`; text `Revert Commit` / `Revert Commits`; description `Produce a new commit(s), which reverts the changes made in the original commit(s)`) creates revert commits; disabled for merge commits (`Reverting merge commits is not allowed`); progress `Reverting <n> commit(s)`. Also available in file history. Applying/reverting selected changes only: `Revert Selected Changes` (`Vcs.RevertSelectedChanges`) and `Cherry-Pick Selected Changes` (`Vcs.ApplySelectedChanges`) from the changes browser apply the diff to the working tree under the changelist `Revert: <name>` / `Apply: <name>`. | Revert a non-merge commit: a commit with the revert message appears on top. |
| VCS-LOG-033 | MUST | `Reset Current Branch to Here...` (see VCS-BR-072) from the log; `Undo Commit...` (`Git.Uncommit`) is enabled only for the last commit of the current branch not pushed to a protected branch (`The selected commit is not the last in the current branch`, text of the failure title `Cannot Undo Commit`): the commit is soft-reset and its changes go into the selected changelist (dialog `Select Target Changelist`), progress `Undoing Last Commit...`, success `Undo commit successful`. | Undo last commit: the changes reappear in Local Changes. |
| VCS-LOG-034 | MUST | `Edit Commit Message...` (`Git.Reword.Commit`, `F2`/`Shift+F6`; description `Change commit message via reword option of git rebase or amend`) opens dialog `Edit Commit Message` with `Edit message for commit <hash> by <author>`; on success the notification `Commit message changed` with action `Undo`; errors: `Could not Edit Commit Message`, `The commit is not in the current branch`, `The commit is already pushed to protected branch '<b>'`, `Selected commit has <n> parents`, `Selected commits are from external repository` / `from different repositories`, `Cannot <op> during rebase` (also merge, cherry-pick, revert), initial commit confirmation `Editing Initial Commit` / `Are you sure you want to edit the initial commit?`. Undo failure texts `Cannot undo commit message edit`, `Repository has already been changed`. | Edit the HEAD~2 message: log shows the new message; Undo restores. |
| VCS-LOG-035 | MUST | `Squash Commits...` (`Git.Squash.Commits`): requires contiguous commits of the current branch; dialog `Squashed Commit Message` with `Edit message for squashed commit`; notification `Commits Squashed` with `Undo`; failures `Could not Squash Commits`. `Drop Commits` (`Git.Drop.Commits`): confirmation `Drop Commit(s)` / `Do you want to drop <n> commit(s) from the <b>branch</b> branch?` (detached form `The repository is in the detached HEAD state. Do you want to drop <n> commit(s)?`; confirmation can be disabled by `Ask for confirmation to drop commits`), notification `Dropped <n> commit(s)`, undo `Cannot undo drop`. `Fixup...` / `Squash Into...` (`Git.Fixup.To.Commit`, `Git.Squash.Into.Commit`) commit local changes as `fixup!`/`squash!` commits for the selected one (error titles `Cannot Create Fixup Commit` / `Cannot Create Squash Commit`; description `Nothing to commit`). `Extract Selected Changes to Separate Commit...` (`Git.InMemory.Extract.Selected.Changes`; dialog `New Commit Message`, `Changes extracted from commit <h> by <author>`, notification `Changes extracted`, error `Selected changes cannot be extracted`) and `Drop Selected Changes` (`Git.Drop.Selected.Changes`; success `Changes dropped`, `Unable to drop all changes from the commit`) edit commits in memory (registry `git.in.memory.commit.editing.operations.enabled` default on, `git.drop.selected.changes.enabled` default on). | Squash two commits: the log shows one commit with the entered message. |
| VCS-LOG-036 | MUST | `Interactively Rebase from Here...` (`Git.Interactive.Rebase`): dialog `Rebasing Commits` with the table columns `Action`, `Hash`, `Subject`; per-row actions `Pick`, `Reword`, `Edit` (`Stop to Edit`), `Squash`, `Fixup`, `Drop`, `Update Ref`; drag/keyboard reordering; link `Reset`; `View Git Commands` (title `Git Commands`); hint on reword `Press <key> to apply changes`; buttons `Start Rebasing`, cancel confirmation `Discard changes and cancel rebase?` with `Discard`/`Continue Rebasing`/`Cancel Rebase`; reword cancel `Cancel Reword` / `Entered commit message will be lost` / `Keep Editing`. `noop` case: `There are no commits to rebase because the current branch is directly below the base branch...` Do you want to continue... The rebase runs in memory when possible (`Rebase successful`; failure falls back with `In-memory rebase failed` / `Falling back to regular rebase`, undo texts `Cannot undo interactive rebase`). When Git itself needs an editor (reword/squash messages) the IDE hosts `Git Commit Message` with `Continue Rebasing` and the generic `Git Editor` dialog for unstructured todo files (`Git Root: <root>`). | Start interactive rebase of 3 commits, set the middle to Drop: the history shows 2 commits. |
