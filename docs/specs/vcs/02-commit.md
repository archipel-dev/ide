## 1. Commit interface selection

|---|---|---|---|

Layout of the non-modal panel (top to bottom): changes tree with checkboxes and the toolbar of
VCS-CHG-023; details/preview splitter; message editor; author/option area (collapsed behind
`Show Commit Options`); button row.

| ID | Pri | Requirement | Acceptance |
|---|---|---|---|
| VCS-CMT-010 | MUST | The message editor shows the placeholder `Commit Message` while empty. Accessible name `Commit Message`. Modal dialog label `Commit Message` with mnemonic C. | Empty editor renders the gray placeholder. |
| VCS-CMT-011 | MUST | The primary button is labelled `Commit` (mnemonic: `Comm&it`; on macOS `Commi&t`). It is the default button of the window and fires on `Ctrl+Enter` (macOS also `Cmd+Enter`). Next to it, primary executors: `Commit and Push...` (`Git.Commit.And.Push.Executor`, `Ctrl+Alt+K`; amend mode text `Amend Commit and Push...`; after failed checks `Commit Anyway and Push...` / `Amend Anyway and Push...`). The drop-down arrow of the button lists the custom executors (`Commit and Rebase...` appears for branches that need it). | Type message, `Ctrl+Enter`: commit runs. |
| VCS-CMT-012 | MUST | The Commit button is disabled while an operation is running or when there is nothing to commit; its tooltip/status explains: `Select files to commit` (no included change), `Specify commit message` (empty message, only when the policy requires one; Git requires a message), `Select files to commit and specify commit message`. With the Git staging area: `Stage files to commit`, `Modify files to commit`, `Stage files to commit and specify commit message`, `Modify files to commit and specify commit message`, `Select roots to commit`, `Resolve conflicts in order to commit`. | Empty message and one included file: status `Specify commit message`. |
| VCS-CMT-013 | MUST | Committing with an empty message in the modal dialog shows title `No Commit Message` and text `Add a summary of your changes in the commit message field`; the non-modal UI keeps the button disabled instead. | VCS-CMT-014 | MUST | Message history: `Commit Message History` (`Vcs.ShowMessageHistory`, `Ctrl+M`) opens a popup of the last 25 distinct messages (newest last); choosing one replaces the editor text. A message is stored on every successful commit; a blank message is never stored; an already stored identical message moves to the end. | Commit `a`, then `b`, then `a`: history order is `b`, `a`. | VCS-CMT-015 | SHOULD | The message editor honors the right margin: setting `Show right margin` (`USE_COMMIT_MESSAGE_MARGIN` default on) with width `Right margin:` default 72 columns, and `Wrap when typing reaches right margin` (`WRAP_WHEN_TYPING_REACHES_RIGHT_MARGIN`, default off). | VCS-CMT-016 | SHOULD | Commit message inspections (Settings > Version Control > Commit): `Blank line between subject and body` (message `Missing blank line between subject and body`, fix `Add blank line`), `Limit subject line` (`Subject cannot exceed {0} characters`, default 72), `Limit body line` (`Body lines cannot exceed {0} characters`, default 72, fix `Wrap line`), `Spelling`. | Subject of 80 chars is underlined with the message text. |

| VCS-CMT-018 | MUST | While an amend is active the editor shows the last commit's message (loading text `Loading Commit Message` in a progress); on error `Commit Message Not Loaded` / `Could not load commit message of the commit to amend.` | Toggle amend: the editor shows the HEAD message. |

## 3. Inclusion, partial commits

| ID | Pri | Requirement | Acceptance |
|---|---|---|---|
| VCS-CMT-020 | MUST | Each change/file node has a checkbox; checked nodes are committed. Unversioned files are shown under `Unversioned Files` with checkboxes (checked = add and commit). Default inclusion: all changes of the active changelist are included; with `PRESELECT_EXISTING_CHANGELIST` (default off) the changelist of the selection is used. | Fresh state: files of the active list are ticked. |
| VCS-CMT-021 | MUST | Inclusion survives refreshes (set by path), including changes moved between changelists. Selecting changes from several changelists is allowed in the tree but a commit from more than one changelist fails with the early check text `Multiple changelists are selected for commit` (Git: `Cannot commit changes from multiple changelists at once`). | Tick files of two lists and commit: the check stops with that text. |
| VCS-CMT-022 | MUST | Partial commit: inside the diff viewer/gutter, chunks or line ranges of a modified file can be excluded; a partially included file is shown with a mixed checkbox and a label `<n> of <m> changes`; only the included ranges are committed, the rest stays as local modification. Actions: `Include Lines into Commit` (`Vcs.Diff.IncludeWholeChangedLinesIntoCommit`), `Split Chunks and Include Selected Lines into Commit` (`Vcs.Diff.IncludeChangedLinesIntoCommit`), `Split Chunks and Exclude Selected Lines from Commit` (`Vcs.Diff.ExcludeChangedLinesFromCommit`); templated texts `Include Current Line into Commit`, `Split Chunk and Include Selected Lines into Commit`, `Exclude Selected Chunks from Commit` etc. Per-chunk checkbox tooltip: `Include into commit`; ignored-part marker text `Some changes in this chunk are now ignored in the diff view. By selecting the checkbox, you will include all the lines indicated by this bar to commit.` | Check only chunk 2 of 3: the commit contains chunk 2; the working file keeps chunks 1 and 3. |
| VCS-CMT-023 | MUST | Partial inclusion is unsupported for some files (binary, other VCS): committing them shows `Partial Commit Is Not Supported` / `Partial commit is not supported for '<path>'. All changes in the selected files will be committed.` | Mixed-state binary file: dialog with that text. |
| VCS-CMT-024 | SHOULD | Partial commit uses the per-file partial changelist model (VCS-CHG-080); chunk state `ExclusionState` has three values: all included, all excluded, partly. The "commit from gutter" placeholder in the gutter popup reads `Commit this change`. | Gutter popup of a chunk offers commit with that placeholder text. |
| VCS-CMT-025 | SHOULD | Dragging files between changelists changes assignment; unversioned files included in a commit are added before commit; the commit legend counts read `modified`, `added`, `deleted` with counts in the modal dialog. | Legend shows `1 modified, 2 added`. |

## 5. Commit checks

Checks run in four execution orders: EARLY (cheap validations that can stop the commit before any
change), MODIFICATION (checks that edit files), LATE (checks that only read), POST_COMMIT (run
after the commit when the project setting allows). Within one order the checks run in registration
order.

| ID | Pri | Requirement | Acceptance |
|---|---|---|---|
| VCS-CMT-040 | MUST | Pipeline: (1) wait for the local-changes refresh (`Performing VCS refresh...`), (2) save committing documents (see `PLAT-SAVE-040..045`; a prompt `Save Files During Commit` / `The following file is currently being committed to the VCS. Saving now could cause inconsistent data to be committed.` / `Save the file now?` with buttons `Save Now`, `Postpone Save` exists for the veto case), (3) EARLY checks, (4) MODIFICATION checks, (5) LATE checks, (6) the VCS commit (`Committing...`), (7) POST_COMMIT checks (`Checking files in commit`, `Collecting affected commits...`). The first failing check ends the run. | Order is observable in the progress text sequence. |
| VCS-CMT-041 | MUST | Failure presentation in the non-modal UI: a notification titled `<Commit> checks failed` (placeholder is the button name, e.g. `Commit checks failed`) with actions `<Commit> Anyway` (text `Commit Anyway`; `Amend Anyway` when amending) and `Show details` (when the problem has a details view); the commit is aborted. In the modal dialog a confirmation titled `Commit Check Failed` offers the buttons `Show Details` (title-cased details action), the commit action name, and `Cancel`; without details only the commit name and `Cancel`. | A failed check never commits unless the user picks the anyway action. |
| VCS-CMT-042 | MUST | Internal error of a check yields the problem texts `Could not check commit: internal error` or `Could not check commit: error in plugin '<name>'` (plus `. <io message>`); `Could not check commit` for unknown. A check disabled during indexing reports `Code analysis is not possible right now` (modal alert `Code Analysis Is Not Possible Right Now`: `Commit checks cannot be performed while <IDE> updates indexes in the background. You can commit the changes without running checks, or you can wait until indexes are built.`). The label `Some commit checks are not available during the project analysis` is shown in the options. | While indexing the label shows; commit anyway works. |
| VCS-CMT-043 | MUST | `Run Commit Checks` (`Vcs.RunCommitChecks`; progress `Running commit checks...`) runs the checks without committing; `Rerun commit checks` tooltip on the status icon. | Action runs the pipeline and shows the same notifications. |
| VCS-CMT-044 | MUST | Setting `Run advanced checks after a commit is done` (`NON_MODAL_COMMIT_POSTPONE_SLOW_CHECKS`, default **on**; description `Failed checks will not prevent a commit`): analysis and TODO checks run as POST_COMMIT; when off they run as LATE and failures block. POST_COMMIT failures show notification `Commit contains problems` with action `Ignore`, and in the push dialog `Commit contains problems: <text>` or `Commit checks are still in progress`. | Setting on: commit succeeds, then the notification may appear. |
| VCS-CMT-045 | MUST | Built-in platform checks and defaults (project workspace): `Reformat code` (`REFORMAT_BEFORE_PROJECT_COMMIT` off), `Rearrange code` (`REARRANGE_BEFORE_PROJECT_COMMIT` off), `Optimize imports` (`OPTIMIZE_IMPORTS_BEFORE_PROJECT_COMMIT` off), `Cleanup` (`CHECK_CODE_CLEANUP_BEFORE_PROJECT_COMMIT` off; label `Cleanup` or `Cleanup with '<profile>' profile`), `Analyze code` (`CHECK_CODE_SMELLS_BEFORE_PROJECT_COMMIT` default **on** in IDEA, off in PyCharm/RubyMine/CLion; labels `Analyze code`, `Analyze code with '<profile>' profile`, `Choose profile`), `Check TODO` (`CHECK_NEW_TODO` default on; label `Check TODO (<filter>)`). Reformat/Rearrange/Optimize/Cleanup are MODIFICATION; Analyze and TODO are POST_COMMIT/LATE (VCS-CMT-044). A run-configuration check (`Run Configuration`) can be added; its failures read `'<name>' failed with exit code <n>`, `'<name>' - <tests result>`, `Failed to start '<name>'` with action `Edit run configuration`. | Defaults match; the options popup lists the checks in the order reformat, rearrange, optimize, cleanup, analyze, TODO, run configuration. |
| VCS-CMT-046 | MUST | Analysis failure dialog (modal): `<N> files contain problems.<br>` / `One error and 2 warnings found.` / `Would you like to review them?`; the single-file form `File <name> contains problems.`; buttons `Review code analysis` and the commit name and `Cancel`. TODO failure text variants: `One added/edited TODO item was found.` / `Would you like to review it?`, `N TODO items were found in changed fragments`, both, and skipped-file counts; button `Review TODO`. Progress texts: `Inspecting code...`, `Applying fixes...`, `Reformatting code...`, `Rearranging code...`, `Optimizing imports...`, `Analyzing code...`, `Checking for TODO...`. | Introduce an error in a changed file with analysis on: the dialog appears with `One error and no warnings found.` |
| VCS-CMT-047 | MUST | Unresolved merge conflicts check (EARLY): text `Files have unresolved conflicts`; modal confirmation `Unresolved Conflicts`: `Are you sure you want to commit changes with unresolved conflicts?`; Git: `Cannot commit changes due to unresolved conflicts.` (title `Unresolved Conflicts`) and `Committing is not possible because you have unmerged files.` | Conflicted file included: commit stops with the text. |
| VCS-CMT-048 | SHOULD | Changes excluded from a merge commit: title `Changes Excluded from Merge Commit`, text `Are you sure you want to exclude these changed files from merge commit?`, button `Commit Anyway`. | Merge in progress, untick a file, commit: the dialog appears. |
