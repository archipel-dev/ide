# 09.6 Java inspections catalog, part 6: Naming, numeric, packaging, performance, portability

Status: specification, clean-room. Written from the IntelliJ IDEA Community sources in our own words; message texts are
quoted from the message bundles. Source paths are cited as `ic: <path>`. Mirrors `docs/specs/inventory/inspections-java-6.md`:
every inspection of that inventory part has exactly one row, grouped by the inventory group headings. Requirement IDs use
the prefix `JAVA-ICB`.

Primary sources: `ic: java/java-backend/resources/META-INF/InspectionGadgets.xml`, `Inspections.xml`, `GlobalInspections.xml`
(registrations), `ic: java/java-analysis-impl/resources/inspectionDescriptions/*.html` (descriptions),
`ic: java/java-analysis-impl/resources/messages/InspectionGadgetsBundle.properties`, `JavaAnalysisBundle.properties`,
`ic: java/openapi/resources/messages/JavaBundle.properties`, `ic: plugins/lombok/src/main/resources/messages/LombokBundle.properties`,
and the inspection classes under `ic: java/java-analysis-impl/src/com/siyeh/ig/` and `ic: java/java-impl/src/com/intellij/codeInspection/`.

How to read a row: **Default** gives the enabled-by-default flag, the default level (`information` = no editor marker, the
fix is only an Alt+Enter intention; `weak warning` = subtle underline; `warning` = yellow wavy) and whether the inspection is
cleanup-eligible (appears in Code | Code Cleanup). **Reports** lists the trigger, **Not reported** the exceptions,
**Range** the highlighted element, **Message** the problem text (`#ref` = text of the highlighted element, `{0}` = argument as
described), **Options** the settings in the inspection's options pane with defaults, **Fixes** the quick fix names exactly as
shown in the Alt+Enter menu. Common framework behavior (severity override, scopes, suppression with `@SuppressWarnings` and
`//noinspection`, batch run, fix-all-in-file) is in `docs/specs/codeinsight/03-inspections.md` and
`docs/specs/java/07-inspections.md` section 7.1 and applies to every row.

Priorities: enabled-by-default inspections are MUST (two cases each: reporting with the fix, and not reporting); default-off
inspections are SHOULD (one case); LATER only with a stated reason.

Highlight range conventions of the inspection base classes (apply unless a row says otherwise): a statement-level problem
highlights the statement's first token (its keyword, e.g. `break`, `if`, `for`, `while`); a method-call problem highlights the
method name (not the qualifier or arguments); a `new`-expression problem highlights the `new` keyword; class, method, field,
variable, parameter and type-parameter problems highlight the name identifier; other problems highlight the whole reported
expression or element. An inspection whose level is `information` shows no editor marker; its fix is then offered only through
Alt+Enter with the caret anywhere on the element.

## Open questions (part 6)

- The shipped default regexes of the field naming kinds (`FieldNamingConvention`) are taken from the source as found; notably the
  non-constant `static` kind defaults to the upper-case constant pattern. Confirm in a running IDE before relying on it.
- `UseOfAWTPeerClass` is LATER (AWT peers are no longer exported API since Java 9); all other inspections of this part are MUST or SHOULD.
- Batch-only inspections (packaging, module and dependency metrics) need a project model with several modules or packages; their
  cases use a `modules:` line and `--- path` separators to describe that model.
- Cases marked `status: unverified` need confirmation in a running IDE (generated names, exact fix names where the bundle uses
  a `{0}` placeholder, rendering of `#ref` for `new` expressions, library-dependent behavior).
