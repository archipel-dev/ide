# 05. Inline

Status: specification. Requirement prefix `REF-INL`. Java in full depth (local variable, pattern
variable, method, constant field, parameter, super class, class to anonymous), Kotlin function and
property inline. Framework rules are in `01-framework.md`. Executable cases:
`cases/05-inline.cases.md`.

ic: `platform/lang-impl/src/com/intellij/refactoring/inline/{InlineRefactoringActionHandler,InlineOptionsDialog}.java`,
`java/java-impl-refactorings/src/com/intellij/refactoring/inline/**`,

## 1. Dispatch

| ID | Pri | Requirement | Acceptance |
|---|---|---|---|
| REF-INL-001 | MUST | `Inline...` (`Ctrl+Alt+N`) finds the element at the caret (the resolved target of a reference wins over the enclosing declaration) and offers it to the registered inline handlers in this order (Java): static import, constant field, local/pattern variable, method, super class (after the "inline to anonymous class" handler), parameter. The first handler that accepts the element runs. If none accepts, the language-generic inliners run; if nothing applies the error hint `Cannot perform refactoring.` + `Caret should be positioned at the name of element to be refactored` (title `Inline`) is shown. The action text becomes `Inline Method...`, `Inline Field...`, `Inline Parameter...`, `Inline Super Class...` for those targets and `Inline...` otherwise. | Case REF-INL-001 case 1. |
| REF-INL-002 | MUST | Compiled elements without sources cannot be inlined: `{0} refactoring cannot be applied: no sources attached`. Kotlin: `Cannot inline '{0}' from a decompiled file`. | Inline a library method: that hint. |

## 2. Inline local variable and pattern variable (Java)

The popup titles use `Inline Variable` (pattern variable: `Inline Pattern Variable`).

| ID | Pri | Requirement | Acceptance |
|---|---|---|---|
| REF-INL-010 | MUST | Invocation on a reference (or the declaration): if the variable has no usages: error `Variable {0} is never used`. If invoked on a declaration, all references are inlined and the declaration removed, without a prompt. If invoked on a reference and there is more than one reference that gets the same definition and the editor setting `Show inline dialog for local variables` is on (default), a chooser popup opens with the rows `This reference only` and `All {N} references and remove the variable` (first row selected; the covered references are highlighted while a row is selected). With the setting off, or only one reference, everything is inlined and the declaration removed. `This reference only` keeps the declaration. The choice is not remembered. | Cases REF-INL-010 case 1-3. |
| REF-INL-011 | MUST | Result: each chosen reference is replaced by the initializer (parenthesized when precedence requires it; a cast is added if the variable type differs and the replacement would change overload resolution; array initializers become `new T[]{...}`; `var`-typed uses keep inference). The declaration is deleted when all references were inlined (comments are preserved next to the remaining code), after normalizing multi-variable declarations (`int a = 1, b = 2;` keeps `b`). A variable assigned later (`x = 1; use(x);` with no initializer) inlines the dominating assignment and removes it. The replaced expressions are highlighted afterwards. | Case REF-INL-011 case 1,2. |
| REF-INL-012 | MUST | Errors (editor hint with `Cannot perform refactoring.` first line, except where noted): `Variable {0} has no initializer` (invoked on declaration), `Cannot find a single definition to inline` (invoked on reference), `Variable {0} is never used before modification`, `Variable '{0}' is accessed for writing` (the writing occurrences are highlighted), `Another variable '{0}' definition is used together with inlined one` (definitions highlighted), `Variable is used as resource reference`, `Variable is declared outside a code block`, `Unable to inline outside try/catch statement`, `Variable {0} is referenced in multiple files`, pattern variable: `Cannot inline pattern variable`. | Case REF-INL-012 case 1. |
| REF-INL-013 | MUST | Unsafe inline: when a variable read by the initializer is modified between the declaration and a use, the chooser first shows the popup titled `Unsafe Inline: Variables Used in Initializer Are Updated` with rows `Highlight {n} conflicting write(s)` (selects and highlights the writes, nothing changes) and `Ignore writes and continue`; only the second proceeds to REF-INL-010. | Case REF-INL-013 case 1. |
| REF-INL-014 | SHOULD | Simple alias: when the initializer is just a reference to another effectively final local of the same type, after the choice the popup offers `Keep '{other}' name` and `Keep '{this}' name`: the first inlines all references to the other variable's name and deletes this variable; the second deletes this variable and renames the other variable to this variable's name. | Case REF-INL-014 case 1. |

## 3. Inline method (Java)

Dialog `Inline Method` (modal): label `Inline method '{name(params)}' with {N} usage(s):` (with the containing class prefix when
invoked on a reference; if counting would be too expensive: `Inline method '{...}':`); radios in this order:
`Inline all usages, remove the method` (mnemonic a), `Inline all usages, keep the method` (e),
`Inline this usage only, keep the method` (k); for library methods the first reads `Inline all usages in the project` and the second is absent; checkboxes `Search in comments and strings`
and `Search for text occurrences` as for rename of methods (REF-REN-040 defaults); `Refactor`, `Preview` (disabled when `this only` is selected), `Cancel`.

| ID | Pri | Requirement | Acceptance |
|---|---|---|---|
| REF-INL-020 | MUST | Initial selection: invoked on a call: `this usage only` when the user last chose it (setting default off), else `all usages, remove` (or `keep` when that was the last choice); a recursive method or a special call form (constructor `this(...)`, method reference with side effects, delegating call) forces `this usage only` with the other radios disabled; invoked on the declaration: `this usage only` disabled. The last choices are remembered. | Case REF-INL-020 case 1. |
| REF-INL-021 | MUST | Errors (hint): `{0} refactoring cannot inline abstract methods` (unless exactly one non-abstract implementation exists: question `An implementation of abstract method is found:\n\n{name}\n\nDo you want to inline this implementation?`), `{0} refactoring cannot inline native methods`, `{0} refactoring cannot be applied to inline non-chaining constructors` (a call `new X(..)` with a following chain call may offer `Do you want to inline the object and the subsequent call?` with action `Inline Object`), `{0} refactoring may not be applied to remove recursive methods.\nYou can inline only individual method calls.`, `{0} refactoring is not supported when return statement interrupts the execution flow`, `Inline cannot be applied to multiline method in constructor call`, `Inline cannot be applied to multiline method in loop condition`, `Cannot inline reference from {0}`, `Method {0} does not have a body`. | Case REF-INL-021 case 1. |
| REF-INL-022 | MUST | Semantics of the substitution: each argument is evaluated exactly once and in order; a parameter that is only read, used at most once, and receives a side-effect free argument is replaced by the argument text; otherwise a local variable named after the parameter (made unique) is declared before the inlined code and initialized with the argument; a parameter assigned inside the body always gets a local. `this` of the inlined method becomes the qualifier of the call (or the receiver expression is stored in a local if needed twice); unqualified member references inside the body are qualified when the call site has a different `this`. `return expr;` as the last statement of a body used in an expression context makes the call expression become `expr`; a body with several returns (single-return conversion) becomes a local result variable with the statements inlined before the use (message in the conflicts dialog: `Inlined method will be transformed to single-return form`); a void body is inserted as statements in place of the call statement. Varargs calls are expanded. Generic type arguments are substituted. | Cases REF-INL-022 case 1-5. |
| REF-INL-023 | MUST | Conflicts (framework dialog): `{0} that is used in inlined method is not accessible from call site(s) in {1}`, `{0} will not be accessible from {1} after inlining`, `{0} will not be accessible when {1} is inlined into {2}`, `Inlined method calls {0} which won't be accessed in {1}`, `Inlined method calls {0} which won't be accessible on qualifier {1}`, `{0} is not accessible from {1}. The refactoring will use accessor {2} instead. Note that subclasses may override the accessor and change the behaviour.`, `Inlined method is used in javadoc`, `Inlined method is used reflectively`, `Inlined method overrides method from {0}` / `Inlined method implements method from {0}`, `Method is used in one or more method references. Proceeding will convert these method references to lambda expressions.`, `Inlined method is used in method reference with side effects in qualifier`. | Case REF-INL-023 case 1. |
| REF-INL-024 | MUST | When `remove the method` is chosen all usages (also in other files, in comments only listed) are inlined first; the method declaration is deleted at the end; if a usage cannot be inlined (reported as conflict) the method is kept. Command name `Inlining Method {name}`. After inlining redundant imports are cleaned (REF-FRM-045). | Case REF-INL-024 case 1. |

## 4. Inline constant field, parameter, classes (Java)

| ID | Pri | Requirement | Acceptance |
|---|---|---|---|
| REF-INL-030 | MUST | Inline Field dialog (`Inline Field`): label `Inline field '{name}' with {N} usage(s):` (`Inline field '{name}':` when not counted), radios `Inline all usages, remove the field`, `Inline all usages, keep the field`, `Inline this usage only, keep the field`, plus the comment/text checkboxes. Applicable to fields with an initializer, or `final` fields that are assigned the same expression in every constructor. Errors: `Field {0} is never used`, `Inline Field refactoring is supported only for final fields` (non-final field with write usages), `Inline Field is not supported for enum constants`, `Field {0} doesn't have an initializer`, `Initializer for variable {0} cannot be a constant initializer`; conflicts `Field initializer refers to {0}, which is not accessible in {1}`, `Inlined field is used in javadoc`, `Inlined field is used reflectively`. A warning conflict is also raised when variables used in the initializer change before the use (REF-INL-013 text). | Case REF-INL-030 case 1,2. |
| REF-INL-031 | SHOULD | Inline Parameter (`Inline Parameter...`): confirmation `Inline parameter '{0}' with initializer '{1}'?` (checkbox `Replace with local variable` for write cases); errors `Inline for varargs parameters is not supported`, `Inline parameter is not supported when method is a part of inheritance hierarchy`, `Inline is not supported for non-project methods`, `Method has no usages`, `Cannot find constant initializer for parameter`, `Constant initializer is not accessible in method body`, `Inlining parameter with write usages is not supported`, `Parameter initializer depends on caller's {0}`, `Parameter initializer depends on {0} which is not accessible inside the parameter's method`. The parameter must receive the *same constant* in all calls. | Case REF-INL-031 case 1. |
| REF-INL-032 | SHOULD | Inline Super Class (`Inline Super Class`, dialog label `Class {0}`, border `Inline`, radios `Inline all references and remove the class`, `Inline this reference only and keep the class`, panel `JavaDoc for Inlined Members` with `As is`, `Copy`, `Move`): moves all members of the superclass into the inheritors (or the selected one) and rewrites types. Errors: `Cannot inline class without inheritors`, `Cannot inline non-project class`, `Cannot inline into anonymous class.`, `Cannot inline into the inner class. Move '{0}' to upper level`, `Constructor matching super not found`, `No consistent substitution found for {0}. Expected '{1}' but found '{2}'.`, `Type parameters do not agree in {0}. Expected {1} but found {2}`. | LATER detail. |
| REF-INL-033 | SHOULD | Inline to Anonymous Class (a class used by exactly the references being inlined, dialog `Inline to Anonymous Class` with radios `Inline all references and remove the class` / `Inline this reference only and keep the class`); restrictions: `Abstract classes cannot be inlined`, `Class cannot be inlined because it calls its own constructor`, `Result of getClass() invocation would be changed`, `Class cannot be inlined because it accesses its own members on another instance`, `Classes which implement multiple interfaces cannot be inlined`, `Classes which have a superclass and implement an interface cannot be inlined`. | LATER detail. |

## 5. Kotlin

| ID | Pri | Requirement | Acceptance |
|---|---|---|---|
| REF-INL-040 | MUST | Inline Function / Inline Property (titles `Inline Function`, `Inline Property`): dialog with radios `Inline all references and remove the function` (or `... and keep the ...`; text `Inline all references and {verb} the {kind} {occurrences}`) and `Inline this reference and keep the {function or property}`, shown when invoked on a reference; invoked on a declaration inlines everything. Local `val`/`var` use the variable inline popup like Java (REF-INL-010) with the same row texts. Results: a call is replaced by the body (expression body: the expression; block body with a final `return`: statements plus result variable when needed; parameters become `val`s when needed; `it`/receivers mapped; named/default arguments evaluated in order; lambdas passed to inline functions are inlined where possible). | Cases REF-INL-040 case 1-3. |
| REF-INL-041 | MUST | Kotlin errors (hint): `Cannot inline property with accessor(s) and backing field`, `Inline Function is not supported for functions with multiple return statements.`, `Inline Function is not supported for functions with return statements not at the end of the body.`, `Inline function is not supported yet` (unsupported shapes), `Inline recursive function is supported only on references`, `Inlining this call would change the target of a super call.`, `The function not found`, `Cannot inline reference from {0} to {1}`, `{0} refactoring cannot be applied to abstract declaration`, `{0} refactoring cannot be applied to expect declaration`, `{0} refactoring cannot be applied to lambda expression without invocation`, `{0} refactoring cannot be applied to anonymous function without invocation`, `The invocation call cannot be resolved`. | Case REF-INL-041 case 1. |
