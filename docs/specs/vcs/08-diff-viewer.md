## 2. Viewers and layout

| ID | Pri | Requirement | Acceptance |
|---|---|---|---|
| VCS-DIFF-010 | MUST | Viewer kinds: `Side-by-side viewer` (toolbar mode `Split`), `Unified viewer` (`Unified`), `Binary file viewer`, `Directory viewer`, error viewer, three-side viewer (merge/staging). Default is side-by-side except in places that default to unified (changes view preview, VCS log preview, file history preview use order Unified first; log view uses Simple then Unified). The user toggles `Split`/`Unified` in the toolbar (diff tool chooser). | Open from Local Changes: unified; from Ctrl+D on two files: side-by-side. |
| VCS-DIFF-011 | MUST | Side-by-side layout: left editor, change connectors drawn in the divider (curved bands between corresponding ranges with accept/revert controls), right editor; title row above each editor showing the content title (`Local`, `Revision <n>`, path) with a charset/line-separator/BOM indicator when different (`UTF-8 BOM` suffix `<name> BOM`) and for read-only content a lock; the vertical scroll position of both sides stays aligned by corresponding lines. `Swap Sides` (`SwapSidesInDiffWindow`). Change `Align Changes In Side-by-Side Diff` (`Vcs.Diff.ToggleDiffAligningMode`, toolbar text `Align Changes Highlighting`; description `Turn on changes alignment for two-sided diff`; `ENABLE_ALIGNING_CHANGES_MODE` default off) inserts blank filler lines so changed blocks line up. | Left 3-line block vs right 5-line block: connector spans both; aligned mode adds 2 filler lines. |
| VCS-DIFF-012 | MUST | Unified layout: single editor with removed lines (red band) before added lines (green band), line-number columns for both sides, inline highlights; the toolbar differs only in not showing connectors; `Select Opposite Diff Pane` etc. do not apply. | Unified shows both versions of a changed line one under the other. |
| VCS-DIFF-013 | MUST | Collapse unchanged fragments (`Collapse Unchanged Fragments`, toggle; also unfold arrows): sections of unchanged lines longer than the context range collapse into a folding marker (`marker: collapsed unchanged lines`); context lines count from the setting `Context lines:` slider with stops `1`, `2`, `4`, `8`, `Disable` (default 4); `EXPAND_BY_DEFAULT` default **true** for ordinary diff places and **false** for the changes view, commit dialog, VCS log view, file history view and intention preview (which also uses context 2, soft wraps on, whitespaces shown, by-line highlight, ignore whitespaces). Expanded ranges are remembered per viewer instance. | Default side-by-side diff shows 4 lines around each change and folds the rest when `Collapse Unchanged Fragments` is on. |
| VCS-DIFF-014 | MUST | `Synchronize Scrolling` toggle (default on, transient): both editors scroll together aligned at the changes; when off each scrolls freely. `Select Opposite Diff Pane` (`Ctrl+Shift+Tab`) moves focus; `Select Position in Opposite Diff Pane` (`Diff.FocusOppositePaneAndScroll`) also scrolls to the corresponding line. | With sync off, scrolling the left editor leaves the right unchanged. |
| VCS-DIFF-015 | MUST | Read-only handling: the viewer shows a lock icon button (`Disable editing` toggle, `READ_ONLY_LOCK` default true) for the local side; with the lock on typing is blocked and hint text `This view is read-only. Enable editing` (patch viewer: `Switch to editing`) appears. Content from VCS revisions is always read-only. | Local side starts locked; clicking `Enable editing` allows edits. |
| VCS-DIFF-016 | SHOULD | Editor settings per place (`SetEditorSettingsAction`, popup title `Settings` / `Appearance`): `Show Whitespaces` (default off), `Show Line Numbers` (default on; off in changes view), `Show Indent Lines` (off), `Use Soft Wraps` (off), `Breadcrumbs` placement (hidden by default), `Highlighting Level` (`Inspections` default, `Syntax`, `None`; menu visible only when registry `diff.highlighting.level.visible` is on, default off), `Sync editor settings`. | Toggling a setting affects both sides. |
| VCS-DIFF-017 | MUST | `Show Diff Settings Popup...` (`Diff.ShowSettingsPopup`, `Ctrl+Shift+D`) opens the popup with, in order: `Highlighting Differences` group (`Lines`, `Words` (default), `Split changes`, `Characters`, `None`), `Ignore Differences` group (`None` default, `Trim whitespaces`, `Ignore whitespaces`, `Ignore whitespaces and empty lines`, `Ignore formatting`, optional `Ignore language-specific changes`), then the toggles of VCS-DIFF-013/014/015/016. Settings are stored per place (`DiffPlaces`) with global shared flags. `Highlight Words` is the equivalent toggle in gutter popups. | The popup lists the groups in the stated order and the selected radio matches the stored policy. |

## 3. Differences, highlighting, navigation

| ID | Pri | Requirement | Acceptance |
|---|---|---|---|
| VCS-DIFF-020 | MUST | Line-level diff: lines are compared exactly (policy None) after normalizing line separators; changes are classified `Inserted`, `Deleted`, `Changed`; adjacent changed lines form one change; inner (word) fragments inside changed blocks are highlighted more intensely when `Words`/`Split changes`/`Characters` apply (words: tokens of letters/digits and individual punctuation; `Characters`: per character; `Split changes` does not squash neighbors into one fragment). With `Lines` no inner highlights. Registry `diff.by.word.deprioritize.line.differences` default false. | Changing one word on a line highlights only that word in addition to the line band. |
| VCS-DIFF-021 | MUST | Whitespace policies: `Trim whitespaces` ignores differences in leading/trailing whitespace of lines; `Ignore whitespaces` ignores all whitespace differences inside lines; `Ignore whitespaces and empty lines` additionally trims changed chunks consisting only of blank lines (chunk trimming); `Ignore formatting` ignores whitespace and language-aware formatting (e.g. line breaks within expressions) via PSI-based comparison where the language provides it, falling back to whitespace ignoring. Ignored changes are drawn as a dimmed (ignored) band, not removed; the commit inclusion area marker for partially ignored chunks says `Some changes in this chunk are now ignored in the diff view.` | With `Ignore whitespaces`, a line with only indentation changes shows no change or the dimmed ignored style. |
| VCS-DIFF-022 | MUST | Difference navigation: `Next Difference` (`NextDiff`, `F7`) and `Previous Difference` (`PreviousDiff`, `Shift+F7`) move the caret to the next/previous change in the focused editor, scrolling it to the vertical center; at the last change of the last file with `Go to the next file after reaching last change` on (`GO_TO_NEXT_FILE_ON_NEXT_DIFFERENCE`, default **true**) the next press moves to the next file after showing the hint `Press again to go to the next file` (previous: `Press again to go to the previous file`). `Compare Next File` (`Diff.NextChange`, `Alt+Shift+Right`) and `Compare Previous File` (`Diff.PrevChange`, `Alt+Shift+Left`) switch files in the chain. A `Go To Change` popup (`action.presentation.go.to.change.text` = `Go To Change`) lists files; the file counter reads `<n>/<m> files` or `No files`. | At the last change of file 1, `F7` shows the hint, `F7` again opens file 2. |
| VCS-DIFF-023 | MUST | Status line (bottom of each viewer): `No differences`, `1 difference`, `<n> differences`; in the commit diff `<n> differences, <m> included (<k> inactive)` style: `5 differences, 3 included (15 inactive)` (inactive = belong to other changelists); with ignoring `Differences ignored`; computing spinner tooltip `Computing differences`. | A diff with 2 changes shows `2 differences`. |
| VCS-DIFF-024 | MUST | Included-in-navigation-history setting (`Include diffs in navigation history:` `Always`, `Until the diff is closed` (default), `Never`). | Default stores diffs only while open. |
| VCS-DIFF-025 | SHOULD | Sound signals (accessibility) when navigating: `Line added`, `Line removed above`, `Line changed`, `Conflict` (group `Diff view`). | Settings list four signals. |
| VCS-DIFF-026 | SHOULD | Search in diffs (`Search In Changes`, `Vcs.Diff.ToggleSearchInChanges`) and combined-diff counters: `<n> results in <file>`, `0+ results in <file>`, `<n> files`. | Find in combined diff counts matches per file. |

## 4. Applying and reverting changes

| ID | Pri | Requirement | Acceptance |
|---|---|---|---|
| VCS-DIFF-030 | MUST | Between two writable sides, each change has gutter controls on the divider: `Accept` (arrow toward the target), `Revert`, `Append` (with a modifier), `Copy`; they copy the chosen side's text of the change to the other editable side as one undoable command named `Replace change` (and for merge `Accept change`, `Ignore change`). The local side is the usual target; with the lock on (VCS-DIFF-015) controls toward it are disabled. Actions: `Accept Left Side` (`Diff.ApplyLeftSide`, `Ctrl+Alt+R`), `Accept Right Side` (`Diff.ApplyRightSide`, `Ctrl+Alt+A`), `Append Left Side` (`Diff.AppendLeftSide`), `Append Right Side` (`Diff.AppendRightSide`) operate on the change under the caret or on the selected lines. Texts: `Accept`, `Revert`, `Append`, `Copy`, `Append to the Left`/`Right`, `Copy Content to Left/Right`. | Click the `>>` arrow on a change: the right text is replaced with the left text for that change only. |
| VCS-DIFF-031 | MUST | Selected-line transfer: with a selection, the accept/revert actions affect only changed lines inside the selection (`{0} selected changes`); `Include into commit` checkboxes (VCS-CMT-022) appear next to changes in commit diffs. | Select 2 lines of a 5-line change and revert: only those lines revert. |
| VCS-DIFF-032 | SHOULD | Undo: edits made via diff actions are in the target document's undo stack; undo in the diff restores the change. | `Ctrl+Z` reverts an applied change. |
| VCS-DIFF-033 | MUST | `Rollback Lines` in the editor's gutter popup (VCS-CHG-076) and `Revert` in diffs share semantics: replace the changed lines with the base. | Verified in cases. |

  changes view (verify).

  Unified; file history Unified; changes view Unified; everything else Simple first.
